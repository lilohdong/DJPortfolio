# DJPortfolio 사이트 기획

> 상태: v3 (T-004 사용자 검수 반영, T-008 콘텐츠 형식 추가, 확인 필요 답변 반영) · 수정일: 2026-11-18
> 스택: SvelteKit + Threlte (확정). 이 문서는 구현 방식이 아니라 사이트 구성, 방문자 경험, 콘텐츠 형식을 다룬다.
> 표기: `확인 필요`는 사용자에게 확인해야 채울 수 있는 자리다. 이 문서와 콘텐츠 파일은 노트에 없는 사실을 지어내지 않는다.

## 0. 한눈에 보기

- 콘셉트: 방문자가 배를 조작해 바다를 돌아다니며 포트폴리오 섬을 하나씩 찾아간다.
- 목적: **구직용**. 가장 중요한 방문자는 채용 담당자다.
- 보기 방식은 두 가지이고 **같은 콘텐츠 파일**을 쓴다.
  - **항해 보기 (기본)**: 배를 몰아 섬에 정박하거나, 지도에서 섬을 눌러 바로 이동하면 상세 패널이 열린다.
  - **목록 보기 (보조, `/list`)**: 조작 없는 한 페이지 문서. 3D가 안 되는 환경, 동작 줄이기 설정, 모바일 기본값, 검색 노출용.
- 원칙
  1. 어떤 내용도 항해를 해야만 볼 수 있어서는 안 된다. 지도 버튼 한 번, 섬 한 번 누르기로 모든 패널에 닿는다.
  2. 지도 버튼은 첫 화면부터 항상 보인다. 조작을 배우지 않은 채용 담당자도 클릭 두 번이면 원하는 프로젝트를 본다.
  3. 콘텐츠는 `content/` 한 곳에서 관리하고, 두 보기가 함께 읽는다. 프로젝트 파일 하나를 추가하면 섬 하나가 생긴다.
  4. 화면 문구는 컴포넌트에 직접 쓰지 않고 문구 파일(ko) 하나에 모은다(§7).

## 1. 섬 구성

### 1.1 섬 목록

섬 이름은 가칭을 그대로 쓴다(결정 D3).

| 섬 | 역할 | 상세 패널에 보여줄 내용 | 콘텐츠 출처 | 랜드마크 |
|---|---|---|---|---|
| **등대섬** — 소개 | 누구인지 30초 안에 전달 | 이름, 한 줄 소개, 자기소개, 사진, 현재 상태, 거주 지역, 주요 링크 | `content/profile.md` | 등대. 바다 어디서나 보이는 기준점 |
| **프로젝트 군도** — 프로젝트 | 사이트의 본론 | 프로젝트마다 섬 하나(§1.2) | `content/projects/*.md` | 프로젝트마다 다른 건물/상징물 |
| **공방섬** — 기술 | 무엇을 다룰 수 있는지 | 분류별 기술, 기술마다 "어디에 썼는지"(프로젝트 연결) | `content/profile.md`의 `skills` | 작업장·크레인 |
| **항로섬** — 경력·학력 | 걸어온 길 | 학력, 경력, 발표·출시 등 활동 | `content/profile.md` | 이정표가 늘어선 부두 |
| **연락 항구** — 연락 | 다음 행동으로 연결 | 이메일, GitHub | `content/profile.md`의 `contact` | 항구·우체통 |

- 기술 숙련도를 막대나 퍼센트로 표시하지 않는다. 대신 그 기술을 쓴 프로젝트로 연결한다.
- 글·발표용 기록섬은 1차 범위에서 제외한다(자료 부족, 결정 D9).
- 연락은 이메일 링크만 둔다. 문의 양식은 만들지 않는다(결정 D7).

### 1.2 프로젝트 섬

- 프로젝트 파일 하나 = 섬 하나. 현재 7개(대표 6 + CPBS)이며, 이후 계속 추가한다. Tank Attack, 도전! 상식 퀴즈, Shivival은 제외했다(결정 D14, D18). CPBS는 결정 D20으로 추가했다.
- `featured: true`인 대표 프로젝트는 큰 섬, 나머지는 작은 섬으로 만든다.
- 패널 구성(위에서 아래로): 이름·한 줄 요약·기간·팀 형태·본인 역할 → 대표 이미지 → 핵심 기여(`highlights`) → 사용 기술 → 링크 → 본문 앞부분과 "자세히 보기"(`/projects/<slug>`).
- **팀원 실명은 싣지 않는다.** 팀 프로젝트는 "4인 팀"처럼 인원 수와 형태, 사용자 본인 역할만 쓴다(결정 D4). 저장소·릴리스 주소에 팀원의 GitHub 계정 이름이 들어 있는 것은 그대로 링크한다(결정 D15).
- 저장소는 공개·비공개 모두 싣는다. 공개 저장소는 링크하고, 비공개 저장소는 `url: null`로 두어 이름만 글자로 표시한다(결정 D16).

### 1.3 바다 위 배치

좌표는 바다 평면의 `x`(동쪽 +), `z`(남쪽 +)이며 단위는 3D 세계 단위(1 ≈ 1m)다. 프로젝트 섬은 등대섬 둘레에 군도처럼 흩어 놓는다. 격자나 원으로 줄 세우지 않는다.

```
                         북 (z −)
                 [Mongscape −22,−68]        [메이플 48,−64]
  [항로섬 −80,−40]
                [NudgeUp −34,−18]      [Calddy 32,−22]
 서                        [등대섬 0,0]                     [CPBS 88,−6]   동
                                            [여론지 48,14]
      [POS PLACE −50,22]
                          ⛵ 시작 (0,30)              [공방섬 70,40]
                 [연락 항구 −30,60]
                         남 (z +)
```

**섬 좌표**

| 섬 | x | z | 크기(반지름) | 조형물(`landmark`) |
|---|---|---|---|---|
| 등대섬 | 0 | 0 | 12 | 등대 |
| Calddy | 32 | −22 | 6 | `calendar` |
| NudgeUp | −34 | −18 | 6 | `bell` |
| 여론지 | 48 | 14 | 6 | `bar-chart` |
| 메이플 할일 알리미 | 48 | −64 | 6 | `checklist` |
| Mongscape | −22 | −68 | 6 | `monkey` |
| POS PLACE | −50 | 22 | 6 | `pos-counter` |
| CPBS | 88 | −6 | 4.5 | `batter` |
| 공방섬 (예약) | 70 | 40 | 10 | |
| 항로섬 (예약) | −80 | −40 | 10 | |
| 연락 항구 (예약) | −30 | 60 | 10 | |
| 배 시작 지점 | 0 | 30 | — | |

공방섬, 항로섬, 연락 항구는 아직 만들지 않았다. 위 자리는 지금 섬들과 겹치지 않게 비워 둔 곳이다.

**권장 방문 순서**: 등대섬(소개) → 프로젝트 섬(`order` 순서) → 공방섬(기술) → 항로섬(경력·학력) → 연락 항구 (결정 D1). 순서는 바다 위 부표 줄로 옅게 표시하고 강제하지 않는다.

**새 프로젝트 섬 자리 고르는 기준**

1. 등대섬에서 35~90 거리. 대표 프로젝트(`featured`)는 등대섬 가까이나 시작 지점에서 보이는 쪽에, 작은 섬(크기 4.5)은 바깥쪽에 둔다. 방향과 거리를 기존 섬과 다르게 해서 두세 개씩 모이고 몇 개는 떨어져 있게 한다.
2. 섬 가장자리끼리 18 이상 띄운다(얕은 물 띠 6씩 + 배가 지나갈 6). 예약한 섬 자리도 같이 피한다.
3. 선착장은 등대섬 쪽을 본다. 선착장과 구경 카메라 자리(선착장 쪽으로 반지름 × 1.9 + 9)가 다른 섬 위에 오지 않게 한다. 지도에서 이름표가 겹치지 않는지 본다.
4. 고른 자리를 콘텐츠 파일의 `island`에 적는다. `island`를 빠뜨리면 등대섬에서 110 넘게 떨어진 바깥 고리에 임시로 놓인다.

바다 경계는 모든 섬을 감싸는 사각형에 여백 40을 더해 계산한다. 미니맵과 지도도 같은 경계로 축척을 맞춘다.
### 1.4 방문 기록

- 정박한 섬은 지도와 섬 목록에 "방문함"으로 표시한다(같은 브라우저에서 유지).
- 전부 방문 보상, 숨은 요소 같은 놀이 요소는 1차 범위에서 제외한다(결정 D9).

## 2. 방문자 흐름 (항해 보기)

### 2.1 첫 진입 화면

데스크톱은 항해 보기로 시작한다(결정 D5). 바다와 배, 멀리 등대가 보이고 그 위에 진입 카드가 놓인다.

```
┌──────────────────────────────────────────┐
│  [이름] · [한 줄 소개]                       │
│  배를 몰아 섬을 찾아가는 포트폴리오입니다.        │
│  지도(🗺)를 누르면 원하는 섬으로 바로 갑니다.    │
│                                          │
│              [ 항해 시작 ]                  │
│                                          │
│  GitHub · 이메일 · 목록으로 보기               │
└──────────────────────────────────────────┘
                                  화면 구석: [🗺 지도] 항상 보임
```

- 목록 보기는 진입 카드 아래 보조 링크 줄에 둔다. 버튼과 같은 크기로 두지 않는다(결정 D5).
- **지도 버튼은 진입 카드가 떠 있을 때부터 항상 보이고 눌린다.** 진입 카드에서 바로 지도를 열어 섬을 고를 수 있다.
- 이름·한 줄 소개·주요 링크는 3D 장면이 로드되기 전에 글자로 먼저 보인다. 로딩 중에도 지도 버튼과 목록 링크는 눌린다.
- 자동으로 목록 보기(`/list`)를 여는 경우: 3D를 띄울 수 없는 환경, 로딩이 기준 시간을 넘긴 경우, "동작 줄이기" 설정을 켠 방문자, 모바일(§3.4). 안내 문구 한 줄과 함께 "항해 보기로 전환" 링크를 둔다.
- 소리는 넣지 않는다(결정 D8).

### 2.2 조작 안내

"항해 시작"을 누르면 카드가 사라지고 화면 아래에 조작 안내가 잠깐 뜬다. 배를 처음 움직이면 사라진다.

| 입력 | 조작 |
|---|---|
| 키보드 | `W/A/S/D` 또는 방향키로 전진·회전, `E` 또는 `Enter`로 정박, `Esc`로 패널 닫기, `M`으로 지도 |
| 마우스 | 지도 버튼 → 섬 누르기로 바로 이동. 가까이 있는 섬은 섬을 직접 눌러 정박 |
| 터치 | 화면 왼쪽 아래 가상 조이스틱, 정박 버튼, 지도 버튼 |

- 첫 목표는 등대섬이다. 시작하자마자 배 앞쪽에 등대가 보이고 "등대섬 →" 표지가 뜬다.
- 조작 안내는 화면 구석의 `?` 버튼으로 다시 볼 수 있다.

### 2.3 섬 접근 → 정박 → 상세 패널

```
항해 중 ──(섬 근처 진입)──▶ 접근 ──(정박 입력)──▶ 정박 ──▶ 패널 열림
   ▲                         │                              │
   │                    (멀어지면)                       (닫기/Esc)
   └─────────────────────────┴──────────────────────────────┘

지도에서 섬 선택 ──(텔레포트)──────────────────────▶ 정박 ──▶ 패널 열림
```

1. **접근**: 섬 가까이 가면 섬 이름표와 "정박하기 (E)" 안내가 뜬다.
2. **정박**: `E`/`Enter`/버튼/섬 누르기. 배가 선착장에 붙고 카메라가 섬 쪽으로 돈다(1초 안팎, 동작 줄이기에서는 즉시).
3. **패널 열림**: 화면 오른쪽(좁은 화면에서는 아래에서 올라오는 시트)에 상세 패널이 열린다.
   - 패널은 일반 글자와 링크로 된 문서다. 스크롤, 글자 선택, 복사, 화면 낭독기 읽기가 모두 된다.
   - "자세히 보기"는 해당 프로젝트 개별 페이지(`/projects/<slug>`)로 간다.
   - 패널 아래 "다음 섬: ○○ →"는 권장 순서의 다음 섬으로 **텔레포트**한다. 프로젝트 군도 안에서는 `order` 순서로 다음 프로젝트 섬, 마지막 프로젝트 다음은 공방섬이다.
4. **출항**: 닫기 버튼 또는 `Esc`. 조작이 돌아온다.

- 자동 정박(가까이 가기만 해도 패널이 열림)은 하지 않는다.
- 패널이 열려 있는 동안 배 조작 키는 패널 스크롤과 충돌하지 않도록 멈춘다.
- 정박 중인 섬은 주소에 반영한다(`/#<섬>`, 프로젝트는 `/#project-<slug>`). 그 주소로 들어오면 그 섬에 정박한 상태로 시작한다.

### 2.4 지도와 텔레포트

v1의 "자동 항해"는 **텔레포트**로 대체한다(결정 D5).

| 위치 | 요소 | 역할 |
|---|---|---|
| 오른쪽 위 | **🗺 지도 버튼** + 작은 미니맵 | 첫 화면부터 항상 보임. 누르면 큰 지도가 열림 |
| 구석 | `?` 조작 안내 | |
| 진입 카드·패널 하단 | "목록으로 보기" 보조 링크 | |

**큰 지도**
- 바다 전체, 섬 위치와 이름, 프로젝트 섬은 이름과 한 줄 요약, 내 배 위치, 방문 여부, 권장 순서 부표 줄.
- 섬을 누르면 지도가 닫히고, 배가 그 섬 선착장으로 **순간 이동**하면서 그 섬의 패널이 바로 열린다.
- 텔레포트 연출은 짧은 화면 전환(0.3~0.5초, 예: 물보라·페이드) 하나. 동작 줄이기에서는 전환 없이 즉시.
- 지도 안에 섬 이름 목록도 함께 둔다. 키보드만으로 지도를 열고(`M`), 목록에서 섬을 골라(`Enter`) 텔레포트할 수 있어야 한다. 이 목록이 항해 보기를 키보드와 화면 낭독기로 쓰는 가장 짧은 길이다.

## 3. 목록 보기 (`/list`, 보조 경로)

대상: 3D가 돌지 않는 환경, 동작 줄이기 설정, 모바일 기본값, 검색 엔진과 링크 미리보기, 그냥 빨리 읽고 싶은 사람.

### 3.1 구조

```
[머리] 이름 · 한 줄 소개 · 주요 링크 · [항해 보기로 전환]
[바로가기] 소개 | 프로젝트 | 기술 | 경력·학력 | 연락
────────────────────────────────────────
1. 소개         — 자기소개, 현재 상태
2. 프로젝트      — 대표 프로젝트(featured) 카드 먼저, 그다음 나머지. 카드 → /projects/<slug>
3. 기술         — 분류별 목록, 기술 → 관련 프로젝트
4. 경력·학력     — 학력, 경력, 활동
5. 연락         — 이메일, GitHub
```

- 순서는 항해의 권장 순서와 같다.
- 제목은 "소개", "프로젝트"처럼 평범한 말로 쓰고, 섬 이름은 보조 표기로만 쓴다.
- 인쇄하거나 PDF로 저장해도 읽을 만해야 한다.

### 3.2 주소 구조

| 주소 | 내용 |
|---|---|
| `/` | 진입 화면 + 항해 보기 |
| `/#<섬>`, `/#project-<slug>` | 해당 섬에 정박한 상태의 항해 보기 |
| `/list` | 목록 보기 전체 |
| `/projects/<slug>` | 프로젝트 개별 페이지. `slug`는 콘텐츠 파일 이름 |

- 검색 엔진과 링크 미리보기가 읽는 것은 `/list`와 `/projects/<slug>`의 글자다. 이 페이지들은 스크립트가 돌지 않아도 내용이 보여야 한다(정적 생성 권장).
- `/`도 스크립트 없이 열면 이름·한 줄 소개·주요 링크와 목록 링크가 보여야 한다.
- 두 보기 사이 전환은 위치를 유지한다. 공방섬에 정박한 채 목록으로 가면 "기술" 구역으로, 목록의 프로젝트에서 항해로 가면 그 섬에 정박한 상태로 간다.

### 3.3 접근성 기준

- 목록 보기와 프로젝트 페이지는 키보드만으로 이용할 수 있고, 제목 단계와 구역 표지가 올바르다.
- 모든 이미지에 대체 글이 있다(콘텐츠 파일의 `images[].alt`).
- 글자와 배경 대비를 충분히 두고, 색만으로 정보를 구분하지 않는다.
- "동작 줄이기" 설정을 따른다.
- 3D 화면은 화면 낭독기에 장식으로 처리하고, 지도의 섬 목록과 패널이 실제 내용 통로가 된다.

### 3.4 모바일

- 모바일에서도 항해 보기를 제공하지만 **기본값은 목록 보기**다(결정 D11). 목록 머리의 "항해 보기로 전환"으로 들어간다.
- 모바일 항해 보기에서도 지도 버튼과 텔레포트는 그대로 쓴다. 터치 조작은 가상 조이스틱과 정박 버튼.

### 3.5 그림 방향

- 3D는 로우폴리로 만든다(결정 D10). 시간대·색감은 3D 세션이 시안으로 제안한다.

## 4. 콘텐츠 파일 형식

콘텐츠는 저장소의 `content/` 아래 Markdown 파일(YAML frontmatter + 본문)로 관리한다.

```
content/
├── profile.md            소개·기술·경력/학력·연락 섬
└── projects/
    ├── calddy.md         프로젝트 하나 = 파일 하나 = 섬 하나
    ├── nudgeup.md
    └── …
```

### 4.1 공통 규칙

- 값이 노트에 없거나 확인이 필요하면 문자열 `"확인 필요"`를 넣는다. 앱은 이 값을 **"없음"으로 취급해 화면에 그리지 않는다**(해당 줄이나 링크를 숨김). 빌드 때 경고로 목록을 출력하면 좋다.
- 공개하지 않는 링크는 `url: null`로 두고 `label`에 사유를 적는다(예: "GitHub 저장소 (비공개)"). 앱은 링크 없이 글자로만 표시한다.
- 이미지 필드(`images[]`, `profile.photo`)는 아래 네 값을 쓴다. `src`, `width`, `height`는 가져오기 스크립트(`npm run images:import`)가 채운다(§5).
  - `src`: `static/` 기준 경로. 앞에 `/`를 붙이지 않는다(예: `content/projects/calddy/calddy-calendar.webp`). 화면에서는 `$app/paths`의 `asset(src)`로 감싸 하위 경로 배포에서도 맞는 주소가 되게 한다.
  - `width`, `height`: 변환된 이미지의 실제 픽셀 크기. `<img>`의 `width`/`height` 속성에 넣어 레이아웃 밀림을 막는다.
  - `source`: 원본 위치. **원본 Obsidian 볼트 루트 기준 상대 경로**다(프로필 사진만 볼트 바깥이라 `../`로 시작). 스크립트를 다시 돌릴 때만 쓰고 **화면에는 쓰지 않는다**.
  - 아직 옮기지 못한 항목은 `src`에 원본 경로나 `"확인 필요"`가 남아 있고 `width`/`height`가 없다. 앱은 `width`가 없는 항목을 아직 옮기지 않은 이미지로 보고 그리지 않는다(제안, 콘텐츠 로더 작업에서 확정).
- 변환된 파일은 `static/content/projects/<slug>/`와 `static/content/profile/`에 있다. WebP, 긴 변 최대 1600px(프로필 사진은 640px), 파일 이름은 원본 이름을 영문 소문자·숫자·`-`로 바꾼 것이다.
- 팀원 실명, 팀원 개인 정보는 어떤 필드에도 넣지 않는다.

### 4.2 프로젝트 파일 (`content/projects/<slug>.md`)

| 필드 | 형식 | 필수 | 설명 |
|---|---|---|---|
| (파일 이름) | `<slug>.md` | 필수 | `slug`는 영문 소문자·숫자·`-`. 주소(`/projects/<slug>`)와 섬 식별자로 쓰인다 |
| `title` | 문자열 | 필수 | 프로젝트 이름 |
| `summary` | 문자열 | 필수 | 한 줄 요약. 지도, 카드, 링크 미리보기에 쓰인다 |
| `period.start` | `"YYYY-MM"` 또는 `"확인 필요"` | 필수 | 시작 월 |
| `period.end` | `"YYYY-MM"` 또는 `"확인 필요"` | 필수 | 끝 월. 진행 중이면 `"진행 중"` |
| `period.note` | 문자열 | 선택 | 일 단위 기간이나 보충 설명 |
| `team.size` | 숫자 또는 `"확인 필요"` | 필수 | 인원 수. 개인이면 1 |
| `team.type` | `"개인"` \| `"팀"` | 필수 | |
| `team.note` | 문자열 | 선택 | "4인 팀, 캡스톤디자인" 같은 보충. 실명 금지 |
| `role` | 문자열 | 필수 | 본인 역할 한두 줄 |
| `stack` | 문자열 배열 | 필수 | 사용 기술. 표시 순서 그대로 |
| `highlights` | 문자열 배열 (3개 안팎) | 필수 | 한 일. 항목마다 짧은 한 문장으로 "무엇을 어떻게 했다"를 쓴다. 본문과 같은 말을 반복하지 않는다. 패널과 카드에 그대로 나온다 |
| `links[]` | `{ type, label, url }` 배열 | 선택 | `type`: `deploy` \| `demo` \| `repo` \| `release` \| `doc`. `url`이 `null`이면 링크 없이 표시 |
| `images[]` | `{ src, alt, caption?, use, width, height, source }` 배열 | 필수(1개 이상) | 첫 항목이 대표 이미지. `alt`는 대체 글, `caption`은 이미지 아래 표시하는 한 구절 설명(본문에 넣는 사진은 필수, 예: "메인 화면 (디자인 시안)"), `use`는 용도 메모(화면에는 안 씀). `src`·`width`·`height`·`source`는 §4.1 |
| `order` | 정수 | 필수 | 노출 순서이자 섬 배치 순서. 파일 사이에 중복 금지 |
| `featured` | 불리언 | 필수 | 대표 프로젝트 여부. `true`면 큰 섬, 목록 앞쪽 |
| `island` | `{ x, z, size, landmark }` | 선택 | 섬 자리와 크기(§1.3). 생략하면 바깥 고리에 임시로 놓인다. `landmark`는 섬 위 조형물 종류: `calendar`, `bell`, `bar-chart`, `checklist`, `monkey`, `pos-counter`, `batter` 중 하나. 없으면 조형물 없이 둔다 |
| `unverified` | 문자열 배열 | 선택 | 확인 필요 항목 메모. **화면에 표시하지 않는다** |
| (본문) | Markdown | 필수 | 아래 "본문 쓰는 법". 패널은 `<!-- more -->` 앞까지, 개별 페이지는 전체 |

본문 쓰는 법 (2026-11-18 사용자 결정, D22):

- 순서는 대표 그림, 무엇을 왜 만들었는지 한두 문장, 내가 한 일, 결과다. 결과는 출시, 릴리스 횟수, 고친 버그, 커밋 수처럼 확인되는 것만 쓰고, 없으면 생략한다. 소제목은 달지 않고 문장은 프로젝트마다 다르게 쓴다.
- `<!-- more -->` 앞(접히지 않는 부분)은 공백 포함 350자 안팎, 많아도 450자. 더 자세한 내용은 `<!-- more -->` 아래에 짧게 둔다.
- 사진은 `![](키)` 한 줄로 관련 문장 바로 앞이나 뒤에 둔다. 앞뒤에 빈 줄을 둔다. 키는 `images[].src`의 파일 이름에서 확장자를 뺀 것이다(`calddy-diary.webp` → `calddy-diary`). 대체 글과 캡션은 앞머리의 `alt`, `caption`을 쓰므로 `![]` 괄호 안은 비운다.
- 본문에 넣지 않은 사진도 `images`에 남겨 둔다. 화면에서 어떻게 보여 줄지는 구현 때 정한다.
- 팀 프로젝트는 줄이면서도 내가 맡은 범위와 다른 팀원이 맡은 범위가 흐려지지 않게 쓴다.

## 5. 프로젝트 추가 방법

1. `content/projects/`에 `<slug>.md` 파일을 하나 만든다. 기존 파일을 복사해 시작하면 편하다.
2. §4.2의 필수 필드를 채운다. 모르는 값은 `"확인 필요"`로 둔다.
3. `order`는 기존 최댓값 + 1로 둔다. 순서를 바꾸고 싶으면 다른 파일의 `order`도 함께 고쳐 중복이 없게 한다.
4. `island`에 섬 자리를 적는다. §1.3의 기준으로 빈자리를 고르고, 조형물을 고르려면 `landmark`도 적는다.
5. 이미지는 원본 볼트에 넣고 `images[]`에 `src`(볼트 루트 기준 원본 경로)와 대체 글(`alt`, 꼭 쓴다), `use`를 적는다. 그다음 가져오기 스크립트를 실행한다.
   ```sh
   npm run images:import -- --vault "C:\Users\rhkdr\바탕 화면\포폴\포트폴리오"
   ```
   볼트 경로는 `PORTFOLIO_VAULT` 환경 변수로 줘도 된다. 스크립트가 WebP로 변환해 `static/content/projects/<slug>/`에 저장하고, `src`를 저장소 경로로 바꾸고, `width`·`height`·`source`를 채운다. 먼저 `--dry-run`으로 할 일만 볼 수 있고, 원본을 바꿨다면 `--force`로 다시 변환한다. 변환된 이미지와 바뀐 콘텐츠 파일을 함께 커밋한다. PDF처럼 이미지가 아닌 파일은 건너뛰므로 PNG/JPG로 먼저 바꿔 둔다.
6. 기술 섬과 연결하려면 `content/profile.md`의 `skills` 항목 `projects`에 새 slug를 추가한다.
7. 로컬에서 항해 보기(지도에 새 섬이 보이는지)와 `/list`, `/projects/<slug>`를 확인한다.

코드, 3D 장면, 문구 파일은 고치지 않는다. 섬 모양을 프로젝트별로 다르게 하고 싶다면 3D 세션이 `slug` 기준 랜드마크 지정 방식을 따로 정한다(정하지 않으면 기본 섬 모양).

빌드 때 검사하면 좋은 것: 필수 필드 누락, `order` 중복, `slug` 형식, `skills[].projects`에 없는 slug, `island` 수동 값끼리 겹침.

## 6. 사용자에게 받아야 할 자료

1차 콘텐츠는 포트폴리오 볼트(`바탕 화면\포폴\포트폴리오`)의 노트에서 옮겼다. 아직 비어 있는 자료는 §8의 확인 필요 목록에 모았다. 그 밖에 사이트 전체에 필요한 것:

| 항목 | 상태 |
|---|---|
| 프로필 사진 | 받음: `바탕 화면\포폴\동준_정장.png` (볼트 바깥). `static/content/profile/photo.webp`로 변환해 저장소에 넣음 |
| 이력서 PDF | 없음 → 이력서 내려받기 기능을 두지 않는다 |

| 회사 경력 | 볼트에 근거 없음 → 항목을 두지 않는다 |
| 사이트 제목과 한 줄 설명 | 탭 제목 "오동준 | 신입", 한 줄 소개 "적응형 개발자" (둘 다 2026-11-18 사용자 확정) |
| 프로젝트 화면 캡처 | 모두 확보. Calddy는 발표 포스터에서 앱 화면 4장, POS PLACE는 팀 결과 보고서(hwp)에 실린 실행 화면 중 본인 담당 화면 4장을 골라 볼트에 저장함 |
| 실제 앱 화면으로 교체할 이미지 | NudgeUp (지금은 디자인 시안을 쓰고 캡션에 표시) |

## 7. 화면 문구 파일 (다국어 대비)

- 1차는 한국어만 제공한다(결정 D6).
- **버튼, 안내, 제목, 빈 상태 메시지 등 화면 문구는 컴포넌트에 직접 쓰지 않는다.** 한국어 문구 파일 하나(예: `src/lib/i18n/ko.ts`, 위치는 프론트엔드 세션이 정함)에 키-값으로 모으고, 컴포넌트는 키로만 참조한다.
- 나중에 영어를 붙일 때 `en` 파일을 추가하고, 콘텐츠는 `content/en/`처럼 언어별 폴더를 두는 방식으로 확장한다. 1차에서는 콘텐츠 폴더를 언어별로 나누지 않는다.
- 섬 이름(등대섬 등)도 문구 파일에 둔다. 콘텐츠 파일에 넣지 않는다.
- 날짜(`YYYY-MM`) 표시 형식도 문구 파일의 함수나 형식 문자열로 처리한다.
