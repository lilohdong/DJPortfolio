# DJPortfolio 사이트 기획

> 상태: 초안 (T-004) · 작성일: 2026-11-18
> 범위: 사이트 구성과 방문자 경험. 구현 방식과 스택(SvelteKit + Threlte 제안, 미확정)은 다루지 않는다.
> 표기: `[사용자 입력 필요]`는 사용자에게 받아야 채울 수 있는 자리다. 이 문서는 개인 정보와 프로젝트 내용을 지어내지 않는다.

## 0. 한눈에 보기

- 콘셉트: 방문자가 배를 조작해 바다를 돌아다니며 포트폴리오 섬을 하나씩 찾아간다.
- 보기 방식은 두 가지이고 **같은 콘텐츠**를 쓴다.
  - **항해 보기**: 배를 몰아 섬에 정박하면 상세 패널이 열린다.
  - **목록 보기**: 조작 없이 한 페이지 문서로 바로 읽는다.
- 원칙
  1. 어떤 내용도 항해를 해야만 볼 수 있어서는 안 된다. 항해 보기의 모든 내용은 목록 보기에 있다.
  2. 바쁜 방문자(채용 담당자)는 진입 후 클릭 한 번 안에 목록 보기에 도달한다.
  3. 항해는 짧다. 조작 설명 없이도 30초 안에 첫 섬에 닿고, 전체를 3~5분에 돌 수 있다.
  4. 콘텐츠는 한 곳에서 관리하고 두 보기가 함께 읽는다. 내용을 고칠 때 두 군데를 고치지 않는다.

## 1. 섬 구성

### 1.1 섬 목록

기본 5개 섬 + 선택 섬. 섬 이름은 가칭이며 사용자가 바꿀 수 있다(§5 Q3).

| # | 섬 (가칭) | 역할 | 상세 패널에 보여줄 내용 | 섬의 모양(식별용 랜드마크) |
|---|---|---|---|---|
| 1 | **등대섬** — 소개 | 누구인지 30초 안에 전달 | 이름·직무 한 줄, 자기소개 2~4문장, 프로필 사진, 현재 상태(구직 중 여부 등), 이력서 내려받기, 주요 링크 | 등대. 바다 어디서나 보이는 기준점 |
| 2 | **공방섬** — 기술 | 무엇을 다룰 수 있는지 | 기술을 분류별로(예: 언어 / 프레임워크 / 인프라 / 도구), 기술마다 숙련도 대신 **"어디에 썼는지"**(관련 프로젝트 연결) | 작업장·크레인 |
| 3 | **프로젝트 군도** — 프로젝트 | 실제로 만든 것. 사이트의 본론 | 프로젝트마다 작은 섬 하나. 내용은 §1.2 | 프로젝트별로 다른 건물/상징물 |
| 4 | **항로섬** — 경력·학력 | 걸어온 길 | 시간순 이력(회사/소속, 기간, 역할, 한 일 2~4개), 학력, 수상·자격·활동 | 이정표가 늘어선 부두 |
| 5 | **연락 항구** — 연락 | 다음 행동으로 연결 | 이메일, GitHub, 그 밖의 링크, (선택) 문의 양식, 이력서 내려받기 | 항구·우체통 |
| 선택 | **기록섬** — 글·발표 | 블로그 글, 발표, 오픈소스 기여 | 글 목록(제목·날짜·바깥 링크) | 서고 |

- 기술 숙련도를 막대나 퍼센트로 표시하지 않는다. 근거가 없는 숫자라서 읽는 사람에게 정보가 되지 않는다. 대신 그 기술을 쓴 프로젝트로 연결한다.
- 선택 섬은 자료가 3건 이상 있을 때만 둔다. 빈 섬은 만들지 않는다.

### 1.2 프로젝트 섬 한 개의 내용

프로젝트 수는 `[사용자 입력 필요]`. 권장은 **대표 3~5개**를 섬으로 두고, 나머지는 군도 안의 "그 밖의 프로젝트" 표지판 하나에 목록으로 묶는 것이다.

패널 구성(위에서 아래로):

1. 프로젝트 이름, 한 줄 설명, 기간, 본인 역할(개인/팀, 팀 규모)
2. 대표 이미지 또는 짧은 영상
3. 무엇을 풀려고 했는가 (문제)
4. 무엇을 만들었는가 (본인이 한 일 위주, 2~4개 항목)
5. 결과 (수치나 성과가 있으면)
6. 사용 기술 (공방섬의 해당 기술과 서로 연결)
7. 링크: 저장소 / 배포 주소 / 문서·발표 자료
8. (선택) 어려웠던 점과 해결 방법 1~2개

패널에는 1~7을 요약해 보여주고, 긴 설명은 "자세히 보기"로 프로젝트별 개별 페이지(§3.2)로 보낸다.

### 1.3 바다 위 배치

등대섬을 가운데에 두고 나머지를 시계 방향으로 한 바퀴 돌도록 배치한다. 시작 지점은 등대섬 바로 남쪽이다.

```
                      북
        ┌──────────────────────────────────┐
        │                                  │
        │   [4 항로섬]        (선택 기록섬)   │
        │                                  │
        │                                  │
   서   │            [1 등대섬]    [2 공방섬] │   동
        │                ▲                 │
        │              ⛵ 시작              │
        │                                  │
        │   [5 연락 항구]   [3 프로젝트 군도]  │
        │                    · · ·         │
        └──────────────────────────────────┘
                      남
```

- **권장 방문 순서**: 1 등대섬 → 2 공방섬 → 3 프로젝트 군도 → 5 연락 항구 → 4 항로섬.
  경력을 먼저 보고 싶은 방문자를 위해 순서는 강제하지 않는다. 표의 번호는 권장 순서가 아니라 섬 식별 번호다.
  - 대안: 1 → 3 → 2 → 4 → 5 (프로젝트를 가장 먼저, 연락을 마지막에). 어느 쪽을 기본으로 할지는 §5 Q4.
- 권장 순서는 바다 위에 **부표 줄**로 옅게 표시한다. 따라가도 되고 무시해도 된다.
- 거리: 이웃한 섬 사이는 항해 10~15초. 가장 먼 두 섬 사이도 30초를 넘기지 않는다.
- 바다 경계: 보이지 않는 벽 대신, 바깥으로 나가면 안개가 짙어지고 배가 천천히 안쪽으로 돌려진다.
- 등대는 바다 어디에서나 보여서 길을 잃었을 때 기준이 된다.
- 프로젝트 군도는 작은 섬들이 가까이 모여 있어 한 번 들어가면 섬 사이 이동이 3~5초다.

### 1.4 방문 기록

- 정박한 섬은 미니맵과 섬 목록에 "방문함"으로 표시한다(같은 브라우저에서 유지).
- 전부 방문했을 때의 보상(예: 깃발, 축하 문구)은 선택 사항이다(§5 Q9). 넣더라도 내용 열람에 조건을 걸지 않는다.

## 2. 방문자 흐름 (항해 보기)

### 2.1 첫 진입 화면

화면이 뜨면 바다와 배, 멀리 등대가 보이고 그 위에 진입 카드가 놓인다.

```
┌─────────────────────────────────────────┐
│  [사용자 이름] · [직무 한 줄]              │
│  배를 몰아 섬을 찾아가는 포트폴리오입니다.   │
│                                         │
│   [ 항해 시작 ]     [ 목록으로 바로 보기 ]  │
│                                         │
│  이력서 내려받기 · GitHub · 이메일          │
└─────────────────────────────────────────┘
```

- 두 버튼은 같은 크기로 나란히 둔다. "목록으로 바로 보기"를 작은 글씨 링크로 숨기지 않는다.
- 이름·직무·주요 링크는 3D 장면이 로드되기 전에 이미 글자로 보여야 한다. 로딩 중에도 목록 보기 버튼은 눌린다.
- 로딩이 길어지거나(기준 시간은 구현 단계에서 정함) 3D를 띄울 수 없는 환경이면 자동으로 목록 보기를 연다. 안내 문구 한 줄과 함께.
- 자동으로 목록 보기를 기본값으로 삼는 경우: 3D 미지원 기기, "동작 줄이기" 설정을 켠 방문자. 모바일의 기본값은 §5 Q5.
- 소리는 기본 꺼짐. 켜는 버튼만 둔다(§5 Q8).

### 2.2 조작 안내

"항해 시작"을 누르면 카드가 사라지고 화면 아래에 조작 안내가 잠깐 뜬다. 배를 처음 움직이면 사라진다.

| 입력 | 조작 |
|---|---|
| 키보드 | `W/A/S/D` 또는 방향키로 전진·회전, `E` 또는 `Enter`로 정박, `Esc`로 패널 닫기, `M`으로 지도, `L`로 목록 보기 |
| 마우스 | 바다의 한 지점을 누르면 그쪽으로 자동 항해. 섬을 누르면 그 섬으로 가서 정박 |
| 터치 | 화면 왼쪽 아래 가상 조이스틱, 또는 바다/섬을 눌러 자동 항해. 정박은 화면에 뜨는 버튼 |

- 누르기 한 번으로 섬까지 가는 **자동 항해**를 반드시 둔다. 키보드 조작에 익숙하지 않은 방문자도 섬을 볼 수 있다.
- 첫 목표는 등대섬이다. 시작하자마자 배 앞쪽에 등대가 보이고 "등대섬 →" 표지가 뜬다.
- 조작 안내는 화면 구석의 `?` 버튼으로 언제든 다시 볼 수 있다.

### 2.3 섬 접근 → 정박 → 상세 패널

```
항해 중 ──(섬 근처 진입)──▶ 접근 ──(정박 입력)──▶ 정박 ──▶ 패널 열림
   ▲                         │                              │
   │                    (멀어지면)                       (닫기/Esc)
   └─────────────────────────┴──────────────────────────────┘
```

1. **접근**: 섬 가까이 가면 섬 이름표와 "정박하기 (E)" 안내가 뜬다. 배 속도가 조금 줄어든다.
2. **정박**: `E`/`Enter`/버튼/섬 누르기. 배가 선착장에 자동으로 붙고 카메라가 섬 쪽으로 돈다(1초 안팎, "동작 줄이기"에서는 즉시 전환).
3. **패널 열림**: 화면 오른쪽(좁은 화면에서는 아래에서 올라오는 시트)에 상세 패널이 열린다. 뒤로 섬이 계속 보인다.
   - 패널은 일반 글자와 링크로 된 문서다. 스크롤, 글자 선택, 복사, 화면 낭독기 읽기가 모두 된다.
   - 패널 안 "자세히 보기"는 해당 내용의 개별 페이지(§3.2)로 간다.
   - 패널 아래에 "다음 섬: ○○ →" 버튼을 둔다. 누르면 패널이 닫히고 다음 섬으로 자동 항해한다.
4. **출항**: 닫기 버튼 또는 `Esc`. 배가 선착장에서 떨어지고 조작이 돌아온다.

- 자동 정박(가까이 가기만 해도 패널이 열림)은 하지 않는다. 지나가다 패널이 튀어나오면 항해가 끊긴다.
- 패널이 열려 있는 동안 배 조작 키는 패널 스크롤과 충돌하지 않도록 멈춘다.
- 정박 중인 섬은 주소에 반영한다(예: `/#projects/<id>`). 그 주소를 공유하면 받은 사람은 그 섬에 정박한 상태로 들어온다.

### 2.4 미니맵과 섬 목록으로 바로 이동

화면에 항상 떠 있는 것:

| 위치 | 요소 | 역할 |
|---|---|---|
| 오른쪽 위 | 미니맵 | 바다 전체, 섬 위치, 내 배 위치와 방향, 방문 여부. 누르면 큰 지도로 펼쳐짐 |
| 왼쪽 위 | 섬 목록 버튼 | 섬 이름 목록(방문 표시 포함). 항목을 고르면 이동 |
| 위쪽 가운데 또는 오른쪽 | "목록 보기" 전환 | 항해 ↔ 목록 보기 전환. 항상 보임 |
| 구석 | `?` 조작 안내, 소리 켬/끔 | |

- 미니맵의 섬이나 섬 목록의 항목을 고르면 그 섬으로 **자동 항해**한다. 항해 중 "건너뛰기"를 누르면 즉시 도착해 정박한다.
- "동작 줄이기" 설정에서는 자동 항해 없이 즉시 도착한다.
- 섬 목록은 키보드만으로 열고 고를 수 있어야 한다. 항해 보기 전체를 키보드와 화면 낭독기로 쓸 수 있게 만드는 가장 짧은 길이 이 목록이다.
- 큰 지도에는 권장 순서의 부표 줄과 섬별 한 줄 설명을 함께 보여준다.

## 3. 일반 목록 보기

대상: 채용 담당자, 모바일 방문자, 검색 엔진, 화면 낭독기·키보드 사용자, 3D가 돌지 않는 환경, 그냥 빨리 읽고 싶은 사람.

### 3.1 구조

조작이 전혀 없는 한 페이지 문서다. 위에서 아래로 읽으면 끝난다.

```
[머리] 이름 · 직무 한 줄 · 이력서 내려받기 · 주요 링크 · [항해 보기로 전환]
[바로가기] 소개 | 기술 | 프로젝트 | 경력 | 연락
────────────────────────────────────────
1. 소개        — 자기소개, 현재 상태
2. 프로젝트     — 카드 목록(대표 프로젝트 먼저), 각 카드 → 개별 페이지
3. 기술        — 분류별 목록, 기술 → 관련 프로젝트
4. 경력·학력    — 시간순
5. (선택) 글·발표
6. 연락        — 이메일, 링크, (선택) 문의 양식
```

- 목록 보기의 순서는 항해의 권장 순서와 달리 **프로젝트를 기술보다 앞에** 둔다. 훑어보는 사람이 가장 먼저 찾는 것이 프로젝트와 경력이기 때문이다.
- 섬 이름(등대섬 등)은 목록 보기에서 보조 표기로만 쓴다. 제목은 "소개", "프로젝트"처럼 평범한 말로 쓴다.
- 인쇄하거나 PDF로 저장해도 읽을 만해야 한다.

### 3.2 주소 구조

| 주소(안) | 내용 |
|---|---|
| `/` | 진입 화면 + 항해 보기 |
| `/list` | 목록 보기 전체 |
| `/projects/<id>` | 프로젝트 개별 페이지(긴 설명, 이미지 여러 장). 항해 패널과 목록 카드의 "자세히 보기"가 모두 여기로 온다 |
| `/#<섬>` | 해당 섬에 정박한 상태의 항해 보기 |

- 주소 이름은 안이다. 확정은 구현 단계에서 한다.
- 검색 엔진과 링크 미리보기(메신저·SNS에 붙였을 때)가 읽는 것은 `/list`와 `/projects/<id>`의 글자다. 이 페이지들은 스크립트가 돌지 않아도 내용이 보여야 한다.
- `/` 역시 스크립트 없이 열면 이름·직무·주요 링크와 목록 보기 링크가 보여야 한다.
- 두 보기 사이 전환은 위치를 유지한다. 공방섬에 정박한 채 목록 보기로 가면 "기술" 구역으로, 목록의 "프로젝트 A"에서 항해 보기로 가면 그 섬에 정박한 상태로 간다.

### 3.3 접근성 기준

- 목록 보기는 키보드만으로 전부 이용할 수 있고, 제목 단계와 구역 표지가 올바르다.
- 모든 이미지에 대체 글이 있다(§4의 자료 요청에 포함).
- 글자와 배경의 대비를 충분히 두고, 색만으로 정보를 구분하지 않는다(방문 여부는 색 + 표시).
- "동작 줄이기" 설정을 따른다.
- 항해 보기의 3D 화면은 화면 낭독기에 장식으로 처리하고, 섬 목록과 패널이 실제 내용 통로가 된다.

### 3.4 모바일

- 좁은 화면에서 목록 보기는 한 줄 세로 배치.
- 항해 보기를 모바일에 제공할지, 기본값을 어느 쪽으로 할지는 §5 Q5.
