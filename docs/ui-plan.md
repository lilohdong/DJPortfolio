# UI 기획안 (T-013)

픽셀 렌더로 그린 바다 위에 흰 둥근 버튼과 기본 패널이 떠 있어서 두 화면이 따로 논다. 이 문서는 화면 요소의 모양과 동선을 픽셀 화면에 맞추는 계획이다. 구현은 df 세션과 3D 세션이 나눠 맡는다. 결정 1, 2, 5는 확정돼 U1~U3 구현이 시작됐고, 나머지 결정은 §4.2에 있다.

2차 보완(T-013 2차): 정박 후 섬 구경(§3.5), 게임 로딩 화면 같은 첫 화면(§3.2), 본문 사이 사진(§3.9), 섬 깃발 로고(§3.10)를 더했다. T-018 레퍼런스 조사의 제안 중 1번(글 순서와 접기)만 쓰고, 2~5번은 보류했다(2026-11-18 사용자 답).

전제:

- 그림 스타일은 픽셀 렌더(기본값, 픽셀 크기 4)로 확정됐다.
- 디자인 시스템 Astryx는 React 전용이라 쓰지 않는다. Tailwind 4 테마 변수와 Svelte 컴포넌트로 직접 만든다.
- 하늘과 바다 색은 KST 시각에 따라 새벽, 낮, 노을, 밤으로 바뀐다(`src/lib/sailing/time-of-day.ts`). 화면 요소는 어느 시간대에도 읽혀야 한다.
- 특정 게임이나 사이트의 화면을 본뜨지 않는다. 각진 테두리와 4px 격자 같은 일반적인 픽셀 표현만 쓴다.

배포 사이트(https://lilohdong.github.io/DJPortfolio/)는 이 세션에서 열어 보지 못했다. §1은 develop(ab68d8c)의 코드를 읽고 적었다.

## 1. 지금 화면의 문제

### 1.1 공통

- 모든 버튼과 패널이 `rounded-xl`, `rounded-2xl` 둥근 모서리에 흰 바탕(`bg-white/90`)과 부드러운 그림자(`shadow-md`, `shadow-2xl`)를 쓴다. 픽셀 화면은 각진 계단 모양인데 그 위에 매끈한 앱 UI가 얹혀 있다.
- 색이 컴포넌트마다 Tailwind 기본 색(`slate`, `sky`, `emerald`, `amber`)으로 흩어져 있다. 테마 변수가 하나도 없어서(`layout.css`는 `@import 'tailwindcss'` 한 줄) 모양을 바꾸려면 파일 다섯 개를 모두 고쳐야 한다.
- 글꼴을 지정하지 않아 운영체제 기본 글꼴이 나온다. Windows와 macOS, 안드로이드에서 모양이 다 다르다.
- 밤 시간대(20시 이후)에는 하늘이 `#0b1530`까지 어두워진다. 흰 패널은 읽히지만 화면에서 혼자 튀고, 반대로 `bg-slate-900/70` 안내 문구는 밤바다에 묻힌다.

### 1.2 첫 진입 (`src/routes/+page.svelte`)

- 기획(`planning.md` §2.1)에 있는 진입 카드가 아직 없다. 들어오면 바로 바다가 보이고, 왼쪽 위에 "DJ Portfolio" 제목과 "목록으로 보기" 링크가 흰 상자 두 개로 떠 있다.
- 이름과 한 줄 소개가 화면 어디에도 없다. 채용 담당자는 누구의 포트폴리오인지 등대섬에 정박해야 알 수 있는데, 등대섬 패널도 아직 자리표시 문구다.
- 제목 상자(`rounded bg-white/80`)와 링크 상자(`rounded bg-white/90 underline`)의 투명도와 여백이 서로 다르다.

### 1.3 항해 HUD (`SailingHud.svelte`)

- 지도 버튼은 흰 알약 모양 버튼에 "지도" 두 글자만 있다. 기획의 미니맵과 `?` 조작 안내 버튼은 없다.
- 정박 안내는 흰 둥근 상자 안에 하늘색 버튼이 들어 있다. 화면에서 가장 자주 눌리는 버튼인데 지도 버튼과 모양이 다르다.
- 조작 안내 문구의 위치가 기기마다 다르다. 데스크톱은 아래(`bottom-6`), 터치 기기는 위(`top-20`)에 뜬다. 데스크톱에서는 정박 안내(`bottom-24`)와 세로로 붙어 있어 둘이 함께 뜨면 한 덩어리처럼 보인다.
- 텔레포트 전환이 흰 화면 페이드(`bg-white`)라서 밤에는 눈부시다.

### 1.4 지도 (`MapOverlay.svelte`)

- 흰 카드 안에 단색 파란 사각형(`bg-sky-700`)을 깔고, 섬은 초록 원(`bg-emerald-500`)으로 그렸다. 바다 화면과 연결되는 느낌이 없다.
- 섬 이름표가 흰 둥근 상자라 섬 위치보다 이름표가 더 눈에 띈다. 섬끼리 28 간격으로 붙어 있어 이름표가 겹칠 수 있다.
- 아래 섬 목록은 카드마다 프로젝트 요약(`caption`)을 그대로 보여 준다. 요약이 긴 프로젝트(POS PLACE, CPBS)는 카드 높이가 들쭉날쭉하다.
- 대표 프로젝트와 나머지, 가 본 섬과 안 가 본 섬을 구분하지 않는다. 방문 기록 기능이 아직 없다.

### 1.5 섬 패널 (`IslandPanel.svelte`)

- 이미지가 나오지 않는다. 콘텐츠 로더(`projects.server.ts`)가 `images`를 화면으로 넘기지 않는다. 프로젝트마다 실행 화면을 3~6장 준비했는데 패널에는 글만 있다.
- 순서가 기간, 팀, 역할, 한 일, 사용 기술, 링크, 소개 본문이다. 링크가 기술 목록 아래로 밀려 있어 "서비스 바로가기"를 찾으려면 스크롤해야 한다.
- 본문 문단을 모두 펼쳐 보여 준다. 여론지는 문단 7개라 데스크톱 패널에서도 세 화면 넘게 스크롤된다. 기획의 "자세히 보기"와 "다음 섬" 버튼이 없다.
- 기간 줄에 가운뎃점(`· {note}`)으로 날짜 메모를 붙인다. 글쓰기 규칙과 맞지 않는다.
- 등대섬 패널은 "소개 섬입니다. 이름, 자기소개, 주요 링크가 이 자리에 들어갈 예정입니다." 자리표시 문구만 있다. `profile.md`의 내용이 화면에 하나도 나오지 않는다.

### 1.6 목록 페이지 (`src/routes/list/+page.svelte`)

- "준비 중입니다" 문구와 돌아가기 링크뿐이다. 모바일 기본 화면(결정 D11)이자 3D가 실패했을 때 가는 곳인데 내용이 없다.
- 프로젝트 개별 페이지(`/projects/<slug>`)도 없다.

### 1.7 모바일

- 패널은 아래 시트(`max-h-[70dvh]`)로 열린다. 패널이 열리면 조이스틱은 사라지므로 겹치지는 않는다. 다만 시트를 끌어 올리거나 내릴 손잡이가 없어서 30% 남은 바다가 쓸모없이 보인다.
- 정박 안내는 조이스틱 위(`bottom-44`) 가운데에 뜬다. 왼손 엄지는 조이스틱에 있으니 정박 버튼은 오른쪽 아래에 있는 편이 누르기 쉽다.
- 왼쪽 위 제목 상자와 오른쪽 위 지도 버튼, 위쪽 조작 안내(`top-20`)가 좁은 화면 윗부분에 몰린다.

## 2. 디자인 토큰

색, 글꼴, 크기, 간격, 테두리를 `src/routes/layout.css`의 Tailwind 4 `@theme` 블록에 모은다. 컴포넌트는 `bg-panel`, `text-ink`, `font-display`처럼 토큰 이름으로만 쓴다. 결정 1은 "어두운 남색 패널"로 확정됐다. 2.1의 밝은 종이 표는 비교용으로 남겨 둔다.

### 2.1 색

패널은 시간대와 상관없이 같은 색을 쓴다. 하늘이 밝을 때는 어두운 패널이 바다와 대비되고, 밤에는 밝은 테두리가 패널 경계를 잡아 준다. 패널 바탕은 불투명도 94%로 두어 뒤의 바다가 거의 비치지 않게 한다(반투명이 심하면 시간대에 따라 글자 대비가 달라진다).

어두운 남색 패널 (확정):

|---|---|---|---|

| `--color-panel-raised` | `#262f45` | 패널 안 카드, 기술 칩, 눌리기 전 버튼 | |
| `--color-ink` | `#eef1f6` | 본문 글자 | 약 14:1 |

| `--color-accent` | `#f2b544` | 주 버튼, 제목 밑줄, 현재 섬 표시. 등대 불빛 색 | 약 9:1 |

### 2.2 글꼴

제목에만 한글 픽셀 글꼴을 쓰고 본문은 읽기 쉬운 고딕으로 둔다(결정 2, 확정). 채용 담당자가 읽는 글은 패널 본문인데, 픽셀 글꼴로 긴 한글 문단을 읽으면 빨리 지친다.

| 역할 | 후보 | 라이선스 | 메모 |
|---|---|---|---|
| 제목, 버튼, 섬 이름 | Galmuri (갈무리) | SIL OFL 1.1 | 한글 비트맵 글꼴. 크기별로 Galmuri11, Galmuri9 등이 있다 |
| 제목 (대안) | Neo둥근모 (NeoDunggeunmo) | SIL OFL 1.1 | 둥근모꼴을 이은 글꼴. 획이 굵어 작은 크기에서 잘 보인다 |
| 본문 | Pretendard | SIL OFL 1.1 | 한글과 영문 폭이 고르다. 동적 서브셋 CSS가 있어 필요한 글자만 내려받는다 |
| 본문 (대안) | Noto Sans KR | SIL OFL 1.1 | Google Fonts에서 바로 쓸 수 있다 |

- 글꼴 파일은 `static/fonts/`에 넣고 GitHub Pages에서 같이 배포한다. 외부 CDN에 기대지 않는다. 한글 글꼴은 크기가 커서, 제목용 픽셀 글꼴은 화면 문구와 섬 이름에 쓰는 글자만 남긴 서브셋을 만든다.
- 픽셀 글꼴은 설계된 크기의 정수배로만 쓴다. 중간 크기로 늘리면 획이 뭉개진다. 각 글꼴의 설계 크기는 배포 문서에서 확인한다.
- `font-display: swap`으로 글꼴이 늦게 와도 글자가 먼저 보이게 한다.
- 라이선스는 구현할 때 각 글꼴 배포 저장소의 LICENSE 파일로 다시 확인하고, 사이트 아래쪽이나 `README.md`에 글꼴 출처를 적는다.

### 2.3 글자 크기 단계

| 토큰 | 크기 / 줄 간격 | 쓰는 곳 |
|---|---|---|
| `--text-caption` | 12px / 16px | 이미지 캡션, 칩 |
| `--text-body` | 15px / 24px | 패널 본문 |
| `--text-body-sm` | 13px / 20px | 기간, 팀, 지도 섬 목록 |
| `--text-title` | 픽셀 글꼴 설계 크기의 2배 | 패널 제목, 진입 카드 이름 |
| `--text-label` | 픽셀 글꼴 설계 크기의 1배 | 버튼, 섬 이름표, 소제목 |

본문 15px는 패널 폭 26rem에서 한 줄에 한글 30자 안팎이 들어가는 크기다.

### 2.4 간격

픽셀 렌더의 픽셀 하나가 4 CSS 픽셀이므로 간격도 4px 단위로 맞춘다. Tailwind 기본 간격 단위가 4px(`--spacing: 0.25rem`)라 따로 바꿀 것은 없다. 대신 홀수 단위(`p-1.5`, `py-0.5`)는 쓰지 않는다.

| 쓰는 곳 | 값 |
|---|---|
| 패널 안쪽 여백 | 20px (`p-5`) |
| 구역 사이 | 24px (`mt-6`) |
| 목록 항목 사이 | 8px (`gap-2`) |
| 화면 가장자리에서 HUD까지 | 16px (`top-4`, `right-4`) |

### 2.5 테두리와 그림자

- 모서리를 둥글리지 않는다. `rounded-*`를 모두 걷어 낸다.
- 패널과 버튼에 2px 실선 테두리(`--color-line`)를 두른다.
- 그림자는 번지지 않는 딱딱한 그림자로 오른쪽 아래 4px에 둔다(`box-shadow: 4px 4px 0 var(--color-shadow)`). 버튼을 누르면 그림자를 없애고 버튼을 4px 내려서 눌린 느낌을 준다.
- 큰 패널은 모서리 한 칸(4px)을 깎은 계단 모양을 쓸 수 있다. 결정 5는 각진 2px 테두리(A)로 확정됐으므로 계단 모서리는 써 본 뒤 다시 정한다. `clip-path`로 깎으면 그림자도 같이 잘리므로, 그림자는 겉 상자에 따로 둔다.
- 초점 표시는 2px 강조색 바깥 테두리(`outline: 2px solid var(--color-accent); outline-offset: 2px`)로 통일한다. 지금은 `ring-sky-500`과 `ring-sky-300`이 섞여 있다.
- `backdrop-blur`는 쓰지 않는다. 픽셀 화면 위에 흐림이 들어가면 계단 모양이 뭉개진다.

### 2.6 Tailwind 4 테마 변수 초안

```css
@import 'tailwindcss';

@font-face {
	font-family: 'Galmuri11';
	src: url('/fonts/Galmuri11-subset.woff2') format('woff2');
	font-display: swap;
}

@theme {
	--font-display: 'Galmuri11', 'Pretendard', sans-serif;
	--font-sans: 'Pretendard', 'Noto Sans KR', system-ui, sans-serif;

	--color-panel: #1b2233;
	--color-panel-raised: #262f45;
	--color-ink: #eef1f6;
	--color-ink-muted: #a9b3c7;
	--color-line: #e9e2cf;
	--color-accent: #f2b544;
	--color-accent-ink: #1b2233;
	--color-link: #8fd3ff;
	--color-shadow: #0a0e18;
	--color-flash: #0a0e18;

	--text-caption: 12px;
	--text-caption--line-height: 16px;
	--text-body-sm: 13px;
	--text-body-sm--line-height: 20px;
	--text-body: 15px;
	--text-body--line-height: 24px;

	--radius-*: initial;
	--shadow-pixel: 4px 4px 0 var(--color-shadow);
}
```

글꼴 경로는 GitHub Pages의 하위 경로(`/DJPortfolio/`)를 타야 하므로, 실제로는 `layout.css`에서 상대 경로를 쓰거나 `+layout.svelte`에서 `asset()`으로 넣는다. `--radius-*: initial`은 둥근 모서리 유틸리티를 아예 없애 실수로 쓰지 못하게 한다.

## 3. 화면별 구성과 동선

### 3.1 30초 안에 프로젝트를 보는 길

채용 담당자는 배를 몰지 않을 수도 있다. 첫 화면에서 두 번 누르면 프로젝트 하나를 볼 수 있게 한다.

```
제목 화면 ──[프로젝트 바로 보기]──▶ 프로젝트 고르기 ──[이름]──▶ 텔레포트 ──▶ 그 섬 정박 화면
    │
    ├──[목록으로 보기]──▶ /list (모든 프로젝트를 한 페이지에서)
    └──[연락처]──▶ 이메일, GitHub
```

- 제목 화면의 "프로젝트 바로 보기"는 3D가 다 불러와지기 전에도 눌린다. 장면이 아직 없으면 바다 대신 제목 화면 배경 위에 패널만 연다. 장면이 준비되면 그 섬에 정박한 상태로 이어진다.
- 정박 화면 바닥의 "다음 섬" 버튼으로 프로젝트를 차례로 넘긴다. 배를 한 번도 몰지 않고 7개를 모두 볼 수 있다.
- 항해 중 "프로젝트"와 "연락처" 버튼을 늘 둘지(T-018 제안 4), "3D 건너뛰고 목록 보기" 링크를 둘지(T-018 제안 5)는 보류, 구현하면서 다시 정한다.
- 스크립트가 꺼져 있으면 제목 화면은 정적 글자로 남고, 메뉴는 `/list`와 `/projects/<slug>` 링크로 동작한다.

### 3.2 첫 화면: 게임 로딩 화면처럼

사용자 의견("첫 화면은 게임의 로딩씬처럼")을 따라 첫 화면을 제목 화면으로 만든다. 게임형 포트폴리오에서 흔히 지적되는 약점은 START 버튼 하나만 있는 첫 화면과, 연락처로 가는 길이 없는 구성이다. 그래서 제목 화면에도 글로 된 길을 처음부터 함께 둔다.

#### 안 B-1. 메뉴가 있는 제목 화면 (확정)

```
┌──────────────────────────────────────────────┐
│                                              │
│              오 동 준          [픽셀 글꼴, 크게] │
│               주니어 개발자                    │
│                                              │
│                                              │
│   ▶ 항해 시작          (불러오는 중이면 흐리게)  │
│     프로젝트 바로 보기                          │
│     목록으로 보기                              │
│     연락처                                    │
│                                              │
│   [■■■■■■□□□□] 개발자 오동준의 바다로 이동 중…    │ ← 로딩 줄
└──────────────────────────────────────────────┘
```

- 배경: 불러오는 동안은 미리 찍어 둔 바다 픽셀 그림 한 장(webp, 100KB 안팎)을 깐다. 장면이 준비되면 그 자리에서 실제 바다로 바뀌고, 카메라가 등대섬 둘레를 천천히 돈다. 동작 줄이기 설정에서는 카메라를 세워 둔다.
- 로딩 표시: 가짜 퍼센트를 쓰지 않는다. 막대는 실제로 지나가는 단계(`SeaCanvas` 청크 import, 첫 프레임 렌더)와 텍스처 `LoadingManager`의 진행 수로 채운다. 글은 단계마다 바꾸지 않고 로딩 줄 한 줄을 쓴다(사용자 결정 T-020). 말줄임표는 문구에 넣지 않고 화면에서 움직이는 점으로 붙인다.
- 제목 화면에 숫자는 넣지 않는다(사용자 결정 T-020).
- 메뉴: 마우스, 터치, 키보드(위아래 화살표와 Enter)로 고른다. "항해 시작"만 로딩이 끝나야 눌리고, 나머지 셋은 처음부터 눌린다. "연락처"는 이메일과 GitHub 링크를 메뉴 아래에 펼친다.
- 다시 방문: 같은 탭에서 항해하다 돌아오면(`sessionStorage`) 제목 화면 없이 바로 바다로 간다. 다른 날 다시 오면(`localStorage`) 제목 화면은 보여 주되, 로딩이 끝나 있으면 "항해 시작"에 초점을 두어 Enter 한 번에 들어가게 한다. 저장소 접근이 막히면 매번 제목 화면을 보여 준다.
- 주소에 `#project-<slug>`가 있으면 제목 화면을 건너뛰고 그 섬에 정박한 상태로 시작한다.
- 항해 중 왼쪽 위 이름표를 누르면 제목 화면으로 돌아간다.

#### 제목 화면 문구 초안

`ko.ts`는 df 세션이 `feature/ui-theme`에서 고치는 중이라 아직 넣지 않았다. 아래 문구를 기획·글 세션이 최종안으로 보고, 키 이름은 df 세션이 정한다.

| 자리 | 문구 | 메모 |
|---|---|---|
| 이름 | 오동준 | `profile.md`의 `name` |
| 한 줄 소개 | 주니어 개발자 | `profile.md`의 `headline` |
| 로딩 줄 | 개발자 오동준의 바다로 이동 중 | 사용자 예시 "개발자 오동준의 바다로 이동중.."에서 띄어쓰기를 고치고 말줄임표를 뺐다 |
| 로딩이 끝났을 때 | 바다에 도착했습니다 | 로딩 줄 자리에 바꿔 넣는다. 막대는 숨긴다 |
| 로딩 실패 | 바다를 불러오지 못했습니다. 목록에서 같은 내용을 볼 수 있습니다. | 지금 `fallback.loadFailed` 자리 |
| 3D를 못 쓰는 브라우저 | 이 브라우저에서는 바다를 띄울 수 없습니다. 목록에서 같은 내용을 볼 수 있습니다. | 지금 `fallback.noWebgl` 자리 |
| 메뉴 1 | 항해 시작 | 로딩 중에는 흐리게 두고, 화면 낭독기에는 "항해 시작, 불러오는 중"으로 읽힌다 |
| 메뉴 2 | 프로젝트 바로 보기 | 누르면 프로젝트 이름 목록이 메뉴 자리에 펼쳐진다 |
| 메뉴 3 | 목록으로 보기 | `/list` |
| 메뉴 4 | 연락처 | 누르면 아래에 이메일 주소와 GitHub 링크가 펼쳐진다 |
| 프로젝트 목록 머리 | 프로젝트 | 메뉴 2를 눌렀을 때. "뒤로"로 메뉴에 돌아간다 |
| 뒤로 | 뒤로 | |

#### 안 B-2. 로딩 화면 뒤 자동으로 바다 (고르지 않음)

- 검은 바탕에 이름과 로딩 막대만 있는 짧은 화면을 보여 주고, 로딩이 끝나면 바로 바다로 넘어간다. 메뉴는 항해 화면 구석에 작게 둔다.
- 누르는 횟수는 가장 적다. 그 대신 로딩하는 몇 초 동안 할 수 있는 일이 없고, 바다에 들어간 뒤 프로젝트로 가는 길을 방문자가 직접 찾아야 한다. 30초 동선이 지도 버튼에 기대게 된다.

### 3.3 항해 HUD

```
┌──────────────────────────────────────────────┐
│ [오동준]                          [지도 M] [?]  │
│                                              │
│                  (바다와 배)                   │
│                                              │
│           [ Calddy 선착장   정박하기 E ]        │
│      W A S D 또는 방향키로 움직입니다 ...        │
└──────────────────────────────────────────────┘
```

- 모든 HUD 요소가 같은 패널 모양(남색 바탕, 2px 테두리, 딱딱한 그림자)을 쓴다.
- 지도 버튼에 단축키 `M`을 작게 붙인다. `?` 버튼은 조작 안내를 다시 띄운다.
- "프로젝트"와 "연락처" 상시 버튼(T-018 제안 4)은 보류, 구현하면서 다시 정한다.
- 왼쪽 위 이름표는 이름만 두고, 누르면 제목 화면으로 간다. "목록으로 보기"는 제목 화면과 `?` 상자 안으로 옮긴다.
- 정박 안내는 화면 아래 가운데에 두고, 정박 버튼만 강조색으로 칠한다. 조작 안내는 그 아래 16px 띄워 두고, 둘이 함께 뜰 때는 조작 안내를 숨긴다.
- 텔레포트 전환은 흰색 대신 `--color-flash`(짙은 남색)로 바꾼다. 동작 줄이기 설정에서는 전환 없이 바로 옮긴다.
- 미니맵은 이번 범위에서 뺀다.

### 3.4 지도

- 바다 그림을 단색 사각형 대신 4px 격자 무늬가 보이는 남색 바다로 그린다. 섬은 둥근 원 대신 각진 사각형으로 그리고, 대표 프로젝트는 한 단계 크게 그린다. 로고가 있는 섬은 사각형 안에 로고를 작게 넣는다.
- 섬 이름표는 바탕 없이 섬 아래에 글자만 두고, 글자에 1px 어두운 테두리를 둘러 바다 위에서 읽히게 한다. 이름표가 겹치는 섬은 이름표를 위쪽으로 돌린다.
- 섬 목록 카드에는 번호(`order`), 이름, 요약 한 줄을 둔다. 요약은 한 줄을 넘으면 말줄임표로 자른다.
- 현재 정박한 섬은 강조색 테두리로 표시한다. 방문 기록(`planning.md` §1.4)이 생기면 가 본 섬에 작은 깃발 표시를 붙인다.

### 3.5 정박 후 섬 구경

사용자 질문: "정박하기 했을 때 섬 안에 들어가서 구경하는 느낌으로는 구현이 불가능한가?" 가능하다. 범위가 다른 세 안을 적는다. 어느 안이든 같은 글과 사진이 목록 페이지와 `/projects/<slug>`에도 그대로 있다. 배를 몰지 않는 방문자도 같은 내용을 읽는다.

먼저 알아 둘 제약이 하나 있다. 3D 장면은 픽셀 렌더라 4px 덩어리로 그려진다. 섬 위 게시판에 실행 화면을 걸어도 3D 안에서는 글자를 읽을 수 없는 거친 그림이 된다. 그래서 어느 안이든 읽을 수 있는 사진과 글은 HTML 패널에 두고, 3D의 게시판은 "여기에 사진이 있다"는 표지 역할만 한다.

#### 안 1. 구경 화면 (확정, 두 단계로 나눠 만든다)

정박하면 카메라가 배 뒤에서 섬 가까이로 옮겨 가 섬을 비스듬히 내려다본다. 섬 언덕에는 로고 깃발이 서 있고, 선착장 옆에 픽셀 게시판이 서 있다. 화면 오른쪽(모바일은 아래)에 글 패널이 열린다. "출항"을 누르면 카메라가 배 뒤로 돌아온다.

1단계: 카메라와 깃발

- 3D: 정박 때 카메라를 섬 쪽으로 옮기는 모드 하나. 섬 중심을 바라보며 좌우로 60도 안에서 끌어 돌려 볼 수 있다(데스크톱은 마우스 끌기, 키보드는 `A`와 `D`). 섬마다 로고 깃발(§3.10). 동작 줄이기에서는 카메라를 바로 옮긴다.
- 콘텐츠 형식: `logo` 필드 하나(§3.10).
- 모바일: 끌어 돌리기는 아래 시트와 손가락이 부딪히므로 넣지 않는다. 카메라는 고정 각도로 둔다.
- 성능: 로고 텍스처 7장(장당 128px 정사각형)만 더해진다. 지금과 거의 같다.
- 작업 크기: 3D 세션 중간, df 세션 작음.

2단계: 게시판과 글 맞추기

- 3D: 선착장 옆 게시판 하나. 패널에서 글을 내리다 사진이 나오면 게시판 그림이 그 사진으로 바뀐다. 게시판을 누르면 패널이 그 사진 위치로 스크롤된다. 게시판 그림은 원본을 작게 줄인 텍스처라 픽셀 렌더에서 거칠게 보이는 것이 맞다.
- 콘텐츠 형식: 본문 사이 사진 표기(§3.9). 1단계와 같은 표기를 그대로 쓴다.
- 모바일: 시트 위쪽에 ◀ ▶ 버튼을 두어 사진 단위로 넘긴다. 게시판과 시트가 같이 바뀐다.
- 성능: 정박한 섬의 사진만 그때 불러온다. 섬 하나에 webp 3~6장, 합쳐서 1MB 안쪽이다. 떠날 때 텍스처를 해제한다.
- 작업 크기: 3D 세션 중간, df 세션 중간.

1단계만으로도 "섬에 들어왔다"는 느낌은 난다. 2단계는 1단계를 써 본 뒤 넣을지 정해도 된다.

#### 안 2. 배에서 내려 섬을 걸어 다니기

- 3D: 걷는 캐릭터 모델과 걷기 동작, 섬 위 충돌 처리, 배와 캐릭터 사이 조작 전환, 걷기용 카메라. 지금 섬 반지름은 4.5~6이라 걸어 다닐 자리가 거의 없다. 섬을 키우면 배치 규칙(`layout.ts`)과 지도도 다시 잡아야 한다.
- 콘텐츠 형식: 섬 안 어디에 무엇을 둘지 정하는 배치 정보가 프로젝트마다 더 필요하다.
- 모바일: 걷기용 조이스틱이 하나 더 필요하고, 시트와 조이스틱이 화면을 나눠 써야 한다.
- 성능: 캐릭터 모델과 애니메이션이 더해진다. 섬 텍스처도 더 세밀해져야 한다.
- 작업 크기: 3D 세션 매우 큼, df 세션 중간. 채용 담당자가 프로젝트 하나를 보려고 걸어 다녀야 해서 30초 동선과도 맞지 않는다.

#### 안 3. 패널만 연다

- 지금처럼 배는 선착장에 머물고 패널만 열린다. 글 사이 사진(§3.9)과 깃발 로고(§3.10)는 그대로 넣는다.
- 3D 작업은 깃발뿐이다. 작업 크기: 3D 세션 작음, df 세션 작음.

### 3.6 정박 화면의 글 패널

안 1과 안 3 모두 이 패널을 쓴다. 데스크톱은 오른쪽 서랍(폭 26rem, 1280px 이상에서 30rem), 모바일은 아래 시트다. 섬이 왼쪽에 보여야 구경 화면이 살기 때문에 결정 3의 "오른쪽 서랍" 안을 그대로 쓴다.

```
┌ 패널 ───────────────────────── [출항 Esc] ┐
│ [로고] Calddy                 [픽셀 글꼴]  │
│ 캘린더에 일기와 친구 피드를 붙인 앱          │
│ 2026년 3월 ~ 6월   4인 팀                  │
│ [GitHub 저장소]                ← 링크 줄    │
├──────────────────────────────────────────┤
│ [대표 이미지]                              │
│ 캘린더와 일정 등록                ← 캡션    │
│                                          │
│ 무엇을 왜 만들었는지 ...                   │
│ 내가 한 일 ...                             │
│ 결과 ...                                  │
│ [이어서 읽기 ▾]          ← 접는 구간       │
│                                          │
│ 역할    백엔드 57개 기능 중 30개를 ...      │
│ 한 일   ▪ 별도 서버 없이 Supabase RLS로 ... │
│                                          │
│ 사용 기술   [Flutter] [Supabase] ...       │
├──────────────────────────────────────────┤
│ [◀ 이전 섬]            [다음 섬: NudgeUp ▶] │
└──────────────────────────────────────────┘
```

- 머리(로고, 제목, 요약, 기간과 팀, 링크 줄)는 스크롤해도 위에 붙어 있다. 비공개 저장소는 회색 글자로 "(비공개)"만 둔다.
- 본문은 대표 그림, 무엇을 왜 만들었는지, 내가 한 일, 결과 순서다(결정 6 B). 접히지 않는 부분은 350자 안팎이다.
- 팀 프로젝트의 "내가 맡은 일" 상자(T-018 제안 2)는 보류, 구현하면서 다시 정한다. 지금은 본문 둘째 문단과 `role`이 담당 범위를 말한다.
- `role`과 `highlights`의 위치(본문 위인지 아래인지)는 U6에서 화면을 보며 정한다.
- 기간 메모(`period.note`)는 가운뎃점 대신 괄호로 붙인다.
- 본문 사이 사진과 접는 구간은 §3.9를 따른다. 사진을 누르면 화면 전체로 크게 본다.
- 바닥 이동 줄의 "다음 섬"은 `order` 순서를 따르고, 마지막 프로젝트 다음은 등대섬이다.

### 3.7 등대섬 패널 (소개)

`profile.md`를 보여 준다.

- 사진, 이름, 한 줄 소개, 상태와 지역
- 소개 두 문장과 요점 세 개
- 기술 분류별 목록. 기술을 누르면 그 기술을 쓴 프로젝트 섬 이름이 버튼으로 펼쳐진다
- 학력, 활동, 자격증
- 이메일, GitHub
- 바닥 이동 줄: "다음 섬: Calddy ▶"

### 3.8 목록 페이지 (`/list`)와 프로젝트 페이지

`planning.md` §3.1 구조를 따르고, 같은 토큰으로 그린다. 페이지 바탕을 패널 색으로 칠해 항해 화면과 같은 사이트로 보이게 한다.

- 머리: 이름, 한 줄 소개, GitHub, 이메일, "항해 보기로 전환"
- 프로젝트 카드: 로고(있으면), 대표 이미지 썸네일, 이름, 요약, 기간과 팀, 기술 칩 4개까지. 대표 프로젝트 6개 먼저, CPBS는 그 아래 "그 밖의 프로젝트"
- 카드를 누르면 `/projects/<slug>`로 간다. 패널과 같은 순서로, 본문 사이 사진을 모두 넣고 접는 구간을 펼친 상태로 보여 준다.
- 인쇄할 때는 바탕을 흰색, 글자를 검은색으로 바꾸는 `@media print` 규칙을 둔다.

### 3.9 본문 사이 사진

사용자 의견("글 안에 사진을 넣는 방식이면 좋겠네")을 따른다. 사진은 지금처럼 앞머리 `images`에 한 번만 적고, 본문에는 어느 사진을 어디에 둘지 이름만 적는다.

표기:

```markdown
일정이 끝난 날짜에는 사진, 동영상, 글로 일기를 남깁니다. ...

![](calddy-diary)

저는 백엔드 57개 기능 중 30개를 맡아 모두 끝냈습니다.

<!-- more -->

서버는 따로 두지 않았습니다. ...
```

- `![](키)` 한 줄을 문단 사이에 둔다. 앞뒤에 빈 줄이 있어야 한다. 키는 `images[].src`의 파일 이름에서 확장자를 뺀 것이다(`content/projects/calddy/calddy-diary.webp` → `calddy-diary`). 새 필드를 만들지 않는다.
- 대체 글과 캡션은 앞머리의 `alt`, `caption`을 쓴다. 본문의 `![]` 괄호 안 글은 비워 둔다. 같은 내용을 두 곳에 적지 않기 위해서다.
- 로더 규칙: `images`에 없는 키를 적으면 빌드를 멈춘다(지금 `title`, `order`가 없을 때와 같은 방식). 한 사진은 본문에 한 번만 쓴다. 로고(§3.10)와 PDF는 본문에 넣을 수 없다.
- 대표 이미지(`use: "대표 이미지"`)는 본문에 적지 않아도 패널 위쪽에 나온다. 본문에 쓰지 않은 나머지 사진은 글 끝 "사진 더 보기"에 모은다.
- `<!-- more -->` 한 줄이 접는 지점이다. 패널은 그 앞까지 보여 주고 "이어서 읽기"로 펼친다. 프로젝트 페이지는 처음부터 펼쳐 둔다. 이 줄이 없으면 접지 않는다.
- 옵시디언이나 GitHub에서 파일을 열면 `![](calddy-diary)`는 깨진 그림으로 보이고 `<!-- more -->`는 보이지 않는다. 사이트 밖 미리보기에는 영향이 없다.

캡션 규칙:

- 본문에 넣는 사진은 `caption`이 꼭 있어야 한다. 없으면 빌드 때 경고한다.
- 캡션은 그 화면이 무엇인지 적는다. 30자 안쪽, 평가하는 말을 넣지 않는다. 가운뎃점으로 나열하지 않는다. 예: "친구 캘린더를 겹쳐 본 화면"
- 디자인 시안은 캡션 끝에 "(디자인 시안)"을 붙인다(NudgeUp).
- `alt`는 화면 낭독기용으로 화면에 보이는 것을 적고, 캡션과 같아도 된다.

기존 파일 옮기기 (기획 세션이 맡는다):

| 프로젝트 | 대표 이미지 | 본문에 넣을 사진 (어느 문단 뒤) | 사진 더 보기 |
|---|---|---|---|
| Calddy | calddy-calendar | calddy-diary (기능 소개 문단), calddy-calendar-overlay (맡은 도메인 문단), calddy-midpoint (지도 재설계 문단) | |
| NudgeUp | nudgeup-main | nudgeup-erd (백엔드 구조 문단), nudgeup-task-create (앱 구조 문단), nudgeup-team-settings (독촉 트랜잭션 문단) | nudgeup-login, nudgeup-signup |
| 여론지 | yeoronji-list-desktop | yeoronji-issue-desktop (층화 추출 문단), yeoronji-nostance-desktop (LLM 문단) | yeoronji-list-mobile, yeoronji-issue-mobile |

- `<!-- more -->` 앞은 공백 포함 350자 안팎(많아도 450자)으로 맞춘다. T-021에서 7개 파일 모두 이 기준으로 줄이고 사진 표기를 넣었다. 실제 배치는 각 파일 본문이 기준이고 위 표는 처음 계획이다.
- Calddy 포스터 PDF 항목은 이미지가 아니므로 계속 화면에 쓰지 않는다.

### 3.10 섬 깃발 로고

사용자 의견("섬 깃발에 로고를 표시하고")을 따른다. 프로젝트 섬마다 언덕 위에 깃발을 세우고 로고를 그린다.

- 필드: 앞머리에 `logo` 하나를 둔다. 모양은 사진 항목과 같다.

```yaml
logo:
  src: "content/projects/calddy/calddy-logo.webp"
  alt: "Calddy 로고"
  width: 128
  height: 128
  source: "프로젝트/Calddy/Calddy_logo.png"
```

- 파일 형식: 투명 바탕 PNG 원본을 넣으면 `npm run images:import`가 128×128 안에 맞춘 webp로 바꾼다. 가져오기 스크립트가 지금은 `images`만 읽으므로 `logo`도 읽게 고친다(df 세션).
- 3D에서는 깃발 천 텍스처로 쓴다. 텍스처 필터를 `NearestFilter`로 두어 픽셀 화면과 같은 각진 모양으로 그린다. 패널 머리와 지도, 목록 카드에서는 32px로 작게 쓴다.
- 로고는 다섯 프로젝트에 있고 모두 `logo` 필드에 적었다(T-021 후속).

| 프로젝트 | 원본 | 상태 |
|---|---|---|
| Calddy | `프로젝트/Calddy/Calddy_logo.png` (492×404) | 변환됨. `images`에서 `logo`로 옮김 |
| NudgeUp | `프로젝트/NudgeUp/nudgeup-logo.png` (99×100) | 변환됨. `images`에서 `logo`로 옮김 |
| 메이플 할일 알리미 | `프로젝트/메이플 할일 알리미/maple-alami-logo.png` (512×512, SVG도 있음) | 변환 전 |
| CPBS | `프로젝트/cpbs/cpbs-logo.png` (180×180, SVG도 있음) | 변환 전 |
| Mongscape | `프로젝트/Mongscape/mongscape-logo.png` (1942×809 가로로 긴 글자 로고, 2.2MB) | 변환 전 |

- 변환 전 항목은 `src`에 원본 경로가 있고 `width`, `height`가 없다. U4에서 가져오기 스크립트가 `logo`를 읽게 되면 변환한다.
- Mongscape 로고는 가로로 길어서 정사각형 깃발에 넣으면 글자가 작아진다. 깃발을 가로로 긴 모양으로 두거나, 깃발에는 앞 글자 "M"을 쓰고 로고는 패널 머리와 목록 카드에만 쓰는 방법이 있다. U8에서 화면을 보고 정한다.
- 로고가 없는 POS PLACE와 여론지는 깃발에 이름 앞 글자("P", "여")를 픽셀 글꼴로 그린다. 깃발 바탕색은 slug로 정해지는 색 하나를 쓴다.

### 3.11 모바일

- 패널은 아래 시트로 열고, 위쪽에 끌기 손잡이를 둔다. 두 높이(화면의 50%, 90%)에 멈춘다. 50%일 때 위쪽에 섬과 깃발이 보인다.
- 시트가 열려 있는 동안 조이스틱과 정박 안내는 숨긴다.
- 정박 버튼은 화면 오른쪽 아래, 조이스틱과 마주 보는 자리에 둔다.
- 조작 안내는 처음 한 번만 화면 위 가운데에 띄우고 3초 뒤 사라진다.
- HUD의 지도와 `?` 버튼은 오른쪽 위에 아이콘 크기로 줄인다.
- 모바일 기본 화면은 목록 페이지다(결정 D11). 위 내용은 "항해 보기로 전환"을 누른 방문자에게 적용된다.
