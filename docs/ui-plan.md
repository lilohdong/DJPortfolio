# UI 기획안 (T-013)

픽셀 렌더로 그린 바다 위에 흰 둥근 버튼과 기본 패널이 떠 있어서 두 화면이 따로 논다. 이 문서는 화면 요소의 모양과 동선을 픽셀 화면에 맞추는 계획이다. 구현은 df 세션이 맡고, 사용자가 §4의 결정 사항을 고르면 시작한다.

전제:

- 그림 스타일은 픽셀 렌더(기본값, 픽셀 크기 4)로 확정됐다.
- 디자인 시스템 Astryx는 React 전용이라 쓰지 않는다. Tailwind 4 테마 변수와 Svelte 컴포넌트로 직접 만든다.
- 하늘과 바다 색은 KST 시각에 따라 새벽, 낮, 노을, 밤으로 바뀐다(`src/lib/sailing/time-of-day.ts`). 화면 요소는 어느 시간대에도 읽혀야 한다.
- 특정 게임이나 사이트의 화면을 본뜨지 않는다. 각진 테두리와 4px 격자 같은 일반적인 픽셀 표현만 쓴다.

배포 사이트(https://lilohdong.github.io/DJPortfolio/)는 이 세션에서 열어 보지 못했다. §1은 develop(ab68d8c)의 코드를 읽고 적었다.

## 1. 지금 화면의 문제

### 1.1 공통

- 모든 버튼과 패널이 `rounded-xl`, `rounded-2xl` 둥근 모서리에 흰 바탕(`bg-white/90`)과 부드러운 그림자(`shadow-md`, `shadow-2xl`)를 쓴다. 픽셀 화면은 각진 계단 모양인데 그 위에 매끈한 앱 UI가 얹혀 있다.
- 색이 컴포넌트마다 Tailwind 기본 색(`slate`, `sky`, `emerald`, `amber`)으로 흩어져 있다. 테마 변수가 하나도 없어서(`layout.css`는 `@import 'tailwindcss'` 한 줄) 모양을 바꾸려면 파일 다섯 개를 모두 고쳐야 한다.
- 글꼴을 지정하지 않아 운영체제 기본 글꼴이 나온다. Windows와 macOS, 안드로이드에서 모양이 다 다르다.
- 밤 시간대(20시 이후)에는 하늘이 `#0b1530`까지 어두워진다. 흰 패널은 읽히지만 화면에서 혼자 튀고, 반대로 `bg-slate-900/70` 안내 문구는 밤바다에 묻힌다.

### 1.2 첫 진입 (`src/routes/+page.svelte`)

- 기획(`planning.md` §2.1)에 있는 진입 카드가 아직 없다. 들어오면 바로 바다가 보이고, 왼쪽 위에 "DJ Portfolio" 제목과 "목록으로 보기" 링크가 흰 상자 두 개로 떠 있다.
- 이름과 한 줄 소개가 화면 어디에도 없다. 채용 담당자는 누구의 포트폴리오인지 등대섬에 정박해야 알 수 있는데, 등대섬 패널도 아직 자리표시 문구다.
- 제목 상자(`rounded bg-white/80`)와 링크 상자(`rounded bg-white/90 underline`)의 투명도와 여백이 서로 다르다.

### 1.3 항해 HUD (`SailingHud.svelte`)

- 지도 버튼은 흰 알약 모양 버튼에 "지도" 두 글자만 있다. 기획의 미니맵과 `?` 조작 안내 버튼은 없다.
- 정박 안내는 흰 둥근 상자 안에 하늘색 버튼이 들어 있다. 화면에서 가장 자주 눌리는 버튼인데 지도 버튼과 모양이 다르다.
- 조작 안내 문구의 위치가 기기마다 다르다. 데스크톱은 아래(`bottom-6`), 터치 기기는 위(`top-20`)에 뜬다. 데스크톱에서는 정박 안내(`bottom-24`)와 세로로 붙어 있어 둘이 함께 뜨면 한 덩어리처럼 보인다.
- 텔레포트 전환이 흰 화면 페이드(`bg-white`)라서 밤에는 눈부시다.

### 1.4 지도 (`MapOverlay.svelte`)

- 흰 카드 안에 단색 파란 사각형(`bg-sky-700`)을 깔고, 섬은 초록 원(`bg-emerald-500`)으로 그렸다. 바다 화면과 연결되는 느낌이 없다.
- 섬 이름표가 흰 둥근 상자라 섬 위치보다 이름표가 더 눈에 띈다. 섬끼리 28 간격으로 붙어 있어 이름표가 겹칠 수 있다.
- 아래 섬 목록은 카드마다 프로젝트 요약(`caption`)을 그대로 보여 준다. 요약이 긴 프로젝트(POS PLACE, CPBS)는 카드 높이가 들쭉날쭉하다.
- 대표 프로젝트와 나머지, 가 본 섬과 안 가 본 섬을 구분하지 않는다. 방문 기록 기능이 아직 없다.

### 1.5 섬 패널 (`IslandPanel.svelte`)

- 이미지가 나오지 않는다. 콘텐츠 로더(`projects.server.ts`)가 `images`를 화면으로 넘기지 않는다. 프로젝트마다 실행 화면을 3~6장 준비했는데 패널에는 글만 있다.
- 순서가 기간, 팀, 역할, 한 일, 사용 기술, 링크, 소개 본문이다. 링크가 기술 목록 아래로 밀려 있어 "서비스 바로가기"를 찾으려면 스크롤해야 한다.
- 본문 문단을 모두 펼쳐 보여 준다. 여론지는 문단 7개라 데스크톱 패널에서도 세 화면 넘게 스크롤된다. 기획의 "자세히 보기"와 "다음 섬" 버튼이 없다.
- 기간 줄에 가운뎃점(`· {note}`)으로 날짜 메모를 붙인다. 글쓰기 규칙과 맞지 않는다.
- 등대섬 패널은 "소개 섬입니다. 이름, 자기소개, 주요 링크가 이 자리에 들어갈 예정입니다." 자리표시 문구만 있다. `profile.md`의 내용이 화면에 하나도 나오지 않는다.

### 1.6 목록 페이지 (`src/routes/list/+page.svelte`)

- "준비 중입니다" 문구와 돌아가기 링크뿐이다. 모바일 기본 화면(결정 D11)이자 3D가 실패했을 때 가는 곳인데 내용이 없다.
- 프로젝트 개별 페이지(`/projects/<slug>`)도 없다.

### 1.7 모바일

- 패널은 아래 시트(`max-h-[70dvh]`)로 열린다. 패널이 열리면 조이스틱은 사라지므로 겹치지는 않는다. 다만 시트를 끌어 올리거나 내릴 손잡이가 없어서 30% 남은 바다가 쓸모없이 보인다.
- 정박 안내는 조이스틱 위(`bottom-44`) 가운데에 뜬다. 왼손 엄지는 조이스틱에 있으니 정박 버튼은 오른쪽 아래에 있는 편이 누르기 쉽다.
- 왼쪽 위 제목 상자와 오른쪽 위 지도 버튼, 위쪽 조작 안내(`top-20`)가 좁은 화면 윗부분에 몰린다.

## 2. 디자인 토큰

색, 글꼴, 크기, 간격, 테두리를 `src/routes/layout.css`의 Tailwind 4 `@theme` 블록에 모은다. 컴포넌트는 `bg-panel`, `text-ink`, `font-display`처럼 토큰 이름으로만 쓴다. 아래 값은 §4 결정 1에서 "어두운 남색 패널"을 고른 경우다. 밝은 종이를 고르면 2.1의 두 번째 표로 바꾼다.

### 2.1 색

패널은 시간대와 상관없이 같은 색을 쓴다. 하늘이 밝을 때는 어두운 패널이 바다와 대비되고, 밤에는 밝은 테두리가 패널 경계를 잡아 준다. 패널 바탕은 불투명도 94%로 두어 뒤의 바다가 거의 비치지 않게 한다(반투명이 심하면 시간대에 따라 글자 대비가 달라진다).

### 2.2 글꼴

제목에만 한글 픽셀 글꼴을 쓰고 본문은 읽기 쉬운 고딕으로 둔다(§4 결정 2의 추천안). 채용 담당자가 읽는 글은 패널 본문인데, 픽셀 글꼴로 긴 한글 문단을 읽으면 빨리 지친다.

| 역할 | 후보 | 라이선스 | 메모 |
|---|---|---|---|
| 제목, 버튼, 섬 이름 | Galmuri (갈무리) | SIL OFL 1.1 | 한글 비트맵 글꼴. 크기별로 Galmuri11, Galmuri9 등이 있다 |
| 제목 (대안) | Neo둥근모 (NeoDunggeunmo) | SIL OFL 1.1 | 둥근모꼴을 이은 글꼴. 획이 굵어 작은 크기에서 잘 보인다 |
| 본문 | Pretendard | SIL OFL 1.1 | 한글과 영문 폭이 고르다. 동적 서브셋 CSS가 있어 필요한 글자만 내려받는다 |
| 본문 (대안) | Noto Sans KR | SIL OFL 1.1 | Google Fonts에서 바로 쓸 수 있다 |

- 글꼴 파일은 `static/fonts/`에 넣고 GitHub Pages에서 같이 배포한다. 외부 CDN에 기대지 않는다. 한글 글꼴은 크기가 커서, 제목용 픽셀 글꼴은 화면 문구와 섬 이름에 쓰는 글자만 남긴 서브셋을 만든다.
- 픽셀 글꼴은 설계된 크기의 정수배로만 쓴다. 중간 크기로 늘리면 획이 뭉개진다. 각 글꼴의 설계 크기는 배포 문서에서 확인한다.
- `font-display: swap`으로 글꼴이 늦게 와도 글자가 먼저 보이게 한다.
- 라이선스는 구현할 때 각 글꼴 배포 저장소의 LICENSE 파일로 다시 확인하고, 사이트 아래쪽이나 `README.md`에 글꼴 출처를 적는다.

### 2.3 글자 크기 단계

| 토큰 | 크기 / 줄 간격 | 쓰는 곳 |
|---|---|---|
| `--text-caption` | 12px / 16px | 이미지 캡션, 칩 |
| `--text-body` | 15px / 24px | 패널 본문 |
| `--text-body-sm` | 13px / 20px | 기간, 팀, 지도 섬 목록 |
| `--text-title` | 픽셀 글꼴 설계 크기의 2배 | 패널 제목, 진입 카드 이름 |
| `--text-label` | 픽셀 글꼴 설계 크기의 1배 | 버튼, 섬 이름표, 소제목 |

본문 15px는 패널 폭 26rem에서 한 줄에 한글 30자 안팎이 들어가는 크기다.

### 2.4 간격

픽셀 렌더의 픽셀 하나가 4 CSS 픽셀이므로 간격도 4px 단위로 맞춘다. Tailwind 기본 간격 단위가 4px(`--spacing: 0.25rem`)라 따로 바꿀 것은 없다. 대신 홀수 단위(`p-1.5`, `py-0.5`)는 쓰지 않는다.

| 쓰는 곳 | 값 |
|---|---|
| 패널 안쪽 여백 | 20px (`p-5`) |
| 구역 사이 | 24px (`mt-6`) |
| 목록 항목 사이 | 8px (`gap-2`) |
| 화면 가장자리에서 HUD까지 | 16px (`top-4`, `right-4`) |

### 2.5 테두리와 그림자

- 모서리를 둥글리지 않는다. `rounded-*`를 모두 걷어 낸다.
- 패널과 버튼에 2px 실선 테두리(`--color-line`)를 두른다.
- 그림자는 번지지 않는 딱딱한 그림자로 오른쪽 아래 4px에 둔다(`box-shadow: 4px 4px 0 var(--color-shadow)`). 버튼을 누르면 그림자를 없애고 버튼을 4px 내려서 눌린 느낌을 준다.
- 큰 패널은 모서리 한 칸(4px)을 깎은 계단 모양을 쓸 수 있다(§4 결정 5). `clip-path`로 깎으면 그림자도 같이 잘리므로, 그림자는 겉 상자에 따로 둔다.
- 초점 표시는 2px 강조색 바깥 테두리(`outline: 2px solid var(--color-accent); outline-offset: 2px`)로 통일한다. 지금은 `ring-sky-500`과 `ring-sky-300`이 섞여 있다.
- `backdrop-blur`는 쓰지 않는다. 픽셀 화면 위에 흐림이 들어가면 계단 모양이 뭉개진다.

### 2.6 Tailwind 4 테마 변수 초안

```css
@import 'tailwindcss';

@font-face {
	font-family: 'Galmuri11';
	src: url('/fonts/Galmuri11-subset.woff2') format('woff2');
	font-display: swap;
}

@theme {
	--font-display: 'Galmuri11', 'Pretendard', sans-serif;
	--font-sans: 'Pretendard', 'Noto Sans KR', system-ui, sans-serif;

	--color-panel: #1b2233;
	--color-panel-raised: #262f45;
	--color-ink: #eef1f6;
	--color-ink-muted: #a9b3c7;
	--color-line: #e9e2cf;
	--color-accent: #f2b544;
	--color-accent-ink: #1b2233;
	--color-link: #8fd3ff;
	--color-shadow: #0a0e18;
	--color-flash: #0a0e18;

	--text-caption: 12px;
	--text-caption--line-height: 16px;
	--text-body-sm: 13px;
	--text-body-sm--line-height: 20px;
	--text-body: 15px;
	--text-body--line-height: 24px;

	--radius-*: initial;
	--shadow-pixel: 4px 4px 0 var(--color-shadow);
}
```

글꼴 경로는 GitHub Pages의 하위 경로(`/DJPortfolio/`)를 타야 하므로, 실제로는 `layout.css`에서 상대 경로를 쓰거나 `+layout.svelte`에서 `asset()`으로 넣는다. `--radius-*: initial`은 둥근 모서리 유틸리티를 아예 없애 실수로 쓰지 못하게 한다.

## 3. 화면별 구성과 동선

### 3.1 30초 안에 프로젝트를 보는 길

채용 담당자는 배를 몰지 않을 수도 있다. 첫 화면에서 두 번 누르면 프로젝트 하나를 볼 수 있게 한다.

```
첫 화면 진입 카드 ──[프로젝트 이름 누르기]──▶ 텔레포트 ──▶ 그 섬 패널 열림
       │
       └──[목록으로 보기]──▶ /list (모든 프로젝트를 한 페이지에서)
```

- 진입 카드 아래쪽에 대표 프로젝트 6개를 이름 버튼으로 늘어놓는다. 누르면 카드가 닫히고 그 섬으로 텔레포트해 패널이 열린다. 지도를 거치지 않는다.
- 패널 맨 아래 "다음 섬" 버튼으로 프로젝트를 차례로 넘긴다. 배를 한 번도 몰지 않고 7개를 모두 볼 수 있다.
- 스크립트가 꺼져 있거나 3D가 안 뜨면 진입 카드의 프로젝트 버튼은 `/projects/<slug>` 링크로 동작한다.

### 3.2 첫 진입 (진입 카드)

```
┌ 진입 카드 (화면 가운데, 폭 28rem) ─────────┐
│ 오동준                     [픽셀 글꼴]    │
│ 직접 배포하고 써 보며 고치는 개발자          │
│ 구직 중 / 경기도 고양시                    │
│                                         │
│ [ 항해 시작 ]          ← 주 버튼, 강조색    │
│                                         │
│ 프로젝트 바로 보기                         │
│ [Calddy] [NudgeUp] [여론지]               │
│ [메이플 할일 알리미] [Mongscape] [POS PLACE] │
│                                         │
│ GitHub   이메일   목록으로 보기            │
└─────────────────────────────────────────┘
                         오른쪽 위: [지도] [?]
```

- 카드는 3D가 불러와지기 전에 글자로 먼저 뜬다. 로딩 문구("바다를 불러오는 중…")는 카드 안 "항해 시작" 버튼 자리에 넣고, 다 불러오면 버튼으로 바꾼다.
- 지금 왼쪽 위에 있는 "DJ Portfolio" 제목 상자와 목록 링크 상자는 없앤다. 이름은 진입 카드가, 항해 중에는 왼쪽 위의 작은 이름표(이름과 "목록으로 보기")가 맡는다.
- "항해 시작"을 누르면 카드가 닫히고 조작 안내가 뜬다. 한 번 닫은 카드는 같은 방문 중에는 다시 띄우지 않는다(`sessionStorage`, 실패하면 매번 띄움).
- 주소에 `#project-<slug>`가 있으면 카드 없이 그 섬 패널부터 연다.

### 3.3 항해 HUD

```
┌──────────────────────────────────────────────┐
│ [오동준 | 목록으로 보기]          [지도 M] [?]  │
│                                              │
│                  (바다와 배)                   │
│                                              │
│           [ Calddy 선착장   정박하기 E ]        │
│      W A S D 또는 방향키로 움직입니다 ...        │
└──────────────────────────────────────────────┘
```

- 모든 HUD 요소가 같은 패널 모양(남색 바탕, 2px 테두리, 딱딱한 그림자)을 쓴다.
- 지도 버튼에 단축키 `M`을 작게 붙인다. 옆에 `?` 버튼을 두고, 누르면 조작 안내를 다시 띄운다.
- 정박 안내는 지금처럼 화면 아래 가운데에 두고, 정박 버튼만 강조색으로 칠한다. 조작 안내는 정박 안내와 겹치지 않게 그 아래 16px 띄워 둔다. 둘 다 뜰 때는 조작 안내를 숨긴다.
- 텔레포트 전환은 흰색 대신 `--color-flash`(짙은 남색)로 바꾼다. 동작 줄이기 설정에서는 지금처럼 전환 없이 바로 옮긴다.
- 미니맵은 이번 범위에서 뺀다. 지도 버튼이 항상 보이고 `M` 한 번에 열리므로 급하지 않다.

### 3.4 지도

- 바다 그림을 단색 사각형 대신 4px 격자 무늬가 보이는 남색 바다로 그린다. 섬은 둥근 원 대신 각진 사각형(픽셀 섬 모양)으로 그리고, 대표 프로젝트는 한 단계 크게 그린다.
- 섬 이름표는 바탕 없이 섬 아래에 글자만 두고, 글자에 1px 어두운 테두리를 둘러 바다 위에서 읽히게 한다. 이름표가 겹치는 섬은 이름표를 위쪽으로 돌린다.
- 섬 목록 카드에는 번호(`order`), 이름, 요약 한 줄을 둔다. 요약은 한 줄을 넘으면 말줄임표로 자른다. 카드 높이가 같아진다.
- 현재 정박한 섬은 강조색 테두리로 표시한다. 방문 기록(`planning.md` §1.4)이 생기면 가 본 섬에 작은 깃발 표시를 붙인다.

### 3.5 섬 패널 (프로젝트)

순서를 "무엇인지, 내가 한 일, 보여 줄 것, 자세한 이야기" 순으로 바꾼다. 위쪽 한 화면 안에 링크까지 들어오게 한다.

```
┌ 패널 ───────────────────────── [닫기 Esc] ┐
│ Calddy                       [픽셀 글꼴]   │
│ 캘린더에 일기와 친구 피드를 붙인 앱          │
│ 2026년 3월 ~ 6월   4인 팀                  │
│ [GitHub 저장소] [서비스 바로가기]  ← 링크 줄 │
├──────────────────────────────────────────┤
│ [대표 이미지]                              │
│ 캡션            ◀ 1 / 4 ▶                 │
│                                          │
│ 역할                                      │
│ 백엔드 57개 기능 중 30개를 설계하고 구현     │
│                                          │
│ 한 일                                     │
│ ▪ 별도 서버 없이 Supabase RLS로 ...        │
│ ▪ ...                                     │
│                                          │
│ 사용 기술   [Flutter] [Supabase] ...       │
│                                          │
│ 소개                                      │
│ 첫 두 문단                                 │
│ [전체 글 보기 ▸]  ← /projects/calddy       │
├──────────────────────────────────────────┤
│ [◀ 이전 섬]                [다음 섬: NudgeUp ▶] │
└──────────────────────────────────────────┘
```

- 머리(제목, 요약, 기간과 팀, 링크 줄)는 스크롤해도 위에 붙어 있게 한다. 링크는 버튼 모양으로 바꾸고, 비공개 저장소는 회색 글자로 "(비공개)"만 둔다.
- 기간 메모(`period.note`)는 가운뎃점 대신 괄호로 붙이거나 마우스를 올렸을 때만 보인다.
- 이미지는 대표 이미지(`use: "대표 이미지"`)를 먼저 보여 주고, 화살표로 나머지를 넘긴다. 로고와 PDF는 넘기는 목록에서 뺀다. 이미지를 누르면 화면 전체로 크게 본다. 세로로 긴 모바일 캡처(CPBS, 여론지 모바일)는 높이를 패널 폭의 1.2배로 자르고 "크게 보기"로 전체를 보여 준다.
- 본문은 첫 두 문단만 보여 주고 "전체 글 보기"로 프로젝트 페이지에 넘긴다. 문단 수가 두 개 이하면 버튼을 두지 않는다.
- 아래쪽 이동 줄은 패널 바닥에 붙여 둔다. "다음 섬"은 `order` 순서를 따르고, 마지막 프로젝트 다음은 등대섬으로 돌아간다(공방섬이 아직 없으므로).
- 패널 폭은 데스크톱에서 26rem 그대로 두고, 1280px 이상 화면에서는 30rem까지 넓힌다. 이미지가 들어가면서 좁은 폭이 답답해진다.

### 3.6 등대섬 패널 (소개)

`profile.md`를 보여 준다. 진입 카드와 내용이 겹치므로 진입 카드보다 한 단계 자세하게 둔다.

- 사진, 이름, 한 줄 소개, 상태와 지역
- 소개 두 문장과 요점 세 개
- 기술 분류별 목록. 기술을 누르면 그 기술을 쓴 프로젝트 섬 이름이 버튼으로 펼쳐진다
- 학력, 활동, 자격증
- 이메일, GitHub
- 아래 이동 줄: "다음 섬: Calddy ▶"

### 3.7 목록 페이지 (`/list`)

`planning.md` §3.1 구조를 그대로 따르고, 같은 토큰으로 그린다. 바다 그림이 없는 대신 페이지 바탕을 패널 색으로 칠해 항해 화면과 같은 사이트로 보이게 한다.

- 머리: 이름, 한 줄 소개, GitHub, 이메일, "항해 보기로 전환"
- 프로젝트 카드: 대표 이미지 썸네일, 이름, 요약, 기간과 팀, 기술 칩 4개까지. 대표 프로젝트 6개 먼저, CPBS는 그 아래 "그 밖의 프로젝트"
- 카드를 누르면 `/projects/<slug>`로 간다. 이 페이지는 패널의 전체 판이다. 이미지를 모두 펼치고 본문 전체를 보여 준다.
- 인쇄할 때는 바탕색을 흰색으로, 글자를 검은색으로 바꾸는 `@media print` 규칙을 둔다.

### 3.8 모바일

- 패널은 아래 시트로 열고, 위쪽에 끌기 손잡이를 둔다. 두 높이(화면의 50%, 90%)에 멈춘다. 처음에는 50%로 열려 머리와 링크, 대표 이미지까지 보인다.
- 시트가 열려 있는 동안 조이스틱과 정박 안내는 숨긴다(지금도 조이스틱은 숨겨진다).
- 정박 버튼은 화면 오른쪽 아래, 조이스틱과 마주 보는 자리에 둔다. 섬 이름은 버튼 위에 작게 쓴다.
- 조작 안내는 첫 진입 때 한 번만 화면 가운데 위에 띄우고 3초 뒤 사라진다. 지금처럼 `top-20`에 계속 남기지 않는다.
- 왼쪽 위 이름표는 모바일에서 이름만 남기고 "목록으로 보기"는 `?` 메뉴 안으로 옮긴다.
- 모바일 기본 화면은 목록 페이지다(결정 D11). 위 내용은 "항해 보기로 전환"을 누른 방문자에게 적용된다.

## 4. 사용자가 고를 것

### 결정 1. 패널 모양

| 선택지 | 모양 | 장단점 |
|---|---|---|
| A. 어두운 남색 (추천) | `#1b2233` 바탕, 밝은 테두리, 밝은 글자 | 낮에는 바다와 대비가 크고 밤에는 테두리가 경계를 잡는다. 픽셀 화면의 색이 패널 옆에서 더 살아 보인다 |
| B. 밝은 종이 | 크림색 `#f6efdc` 바탕, 짙은 테두리, 짙은 글자 | 긴 글을 읽기 편하다. 밤 화면에서 혼자 밝게 튄다 |
| C. 양피지 질감 | B에 종이 무늬와 찢긴 가장자리 | 분위기는 강하지만 무늬 이미지를 따로 그려야 하고, 무늬 위 글자 대비를 맞추기 어렵다 |

### 결정 2. 글꼴 조합

| 선택지 | 내용 | 장단점 |
|---|---|---|
| A. 제목만 픽셀 (추천) | 제목, 버튼, 섬 이름은 Galmuri, 본문은 Pretendard | 픽셀 분위기를 내면서 긴 글은 편하게 읽힌다 |
| B. 전부 픽셀 | 본문까지 Galmuri | 화면이 하나로 묶이지만 한글 긴 문단을 읽기 힘들다. 글꼴 서브셋을 만들 수 없어 파일이 커진다 |
| C. 픽셀 없음 | 전부 Pretendard | 가장 읽기 쉽고 가볍다. 화면 요소가 픽셀 바다와 따로 노는 문제가 절반만 풀린다 |

### 결정 3. 패널이 열리는 위치

| 선택지 | 내용 | 장단점 |
|---|---|---|
| A. 오른쪽 서랍, 모바일은 아래 시트 (추천) | 지금 구조를 유지 | 패널을 열어도 왼쪽에 섬과 배가 보인다. 이미 구현돼 있어 손이 덜 간다 |
| B. 가운데 카드 | 화면 가운데 큰 카드, 뒤 바다는 어둡게 | 이미지를 크게 보여 줄 수 있다. 바다가 가려져 "섬에 왔다"는 느낌이 줄어든다 |
| C. 아래 시트 (데스크톱 포함) | 모든 화면에서 아래에서 올라옴 | 기기별 모양이 같아진다. 넓은 화면에서 글 줄이 너무 길어진다 |

### 결정 4. 첫 화면에서 프로젝트로 가는 길

| 선택지 | 내용 | 장단점 |
|---|---|---|
| A. 진입 카드에 프로젝트 버튼 (추천) | 카드 아래에 대표 프로젝트 6개 이름 버튼 | 두 번 눌러 프로젝트에 닿는다. 카드가 조금 길어진다 |
| B. 지도로 안내 | 카드에는 "지도에서 섬 고르기" 버튼 하나 | 카드가 짧다. 지도를 한 번 거쳐야 해서 세 번 눌러야 한다 |
| C. 카드 없이 바로 바다 | 지금처럼 카드 없이 시작, 등대섬 앞에 배를 둔다 | 가장 단순하다. 배를 몰 줄 모르는 방문자가 길을 잃는다 |

### 결정 5. 모서리와 그림자

| 선택지 | 내용 | 장단점 |
|---|---|---|
| A. 각진 2px 테두리와 딱딱한 그림자 (추천) | 모든 상자에 같은 규칙 | 구현이 간단하고 어디서나 같은 모양이 나온다 |
| B. A에 계단 모서리 추가 | 큰 패널만 모서리 한 칸을 깎는다 | 더 픽셀답다. `clip-path`와 그림자를 따로 다뤄야 해서 손이 간다 |
| C. 테두리 없이 그림자만 | 2px 테두리를 빼고 딱딱한 그림자만 | 화면이 가볍다. 밤 시간대에 패널 경계가 흐려진다 |

## 5. 구현 순서

df 세션이 아래 순서로 나눠 작업한다. 단위마다 feature 브랜치 하나, 끝나면 `?t=12`(낮)과 `?t=21`(밤), 모바일 폭(390px)에서 화면을 확인한다.

| 순서 | 작업 단위 | 고치는 곳 | 크기 |
|---|---|---|---|
| U1 | 테마 변수와 글꼴. `@theme` 블록, 글꼴 파일과 서브셋, 글꼴 출처 표기 | `layout.css`, `static/fonts/`, `README.md` | 작음 |
| U2 | 공통 부품. 패널 상자, 주 버튼, 보조 버튼, 칩을 Svelte 컴포넌트나 `@utility`로 만든다 | `src/lib/ui/` 새 파일 | 작음 |
| U3 | HUD와 지도 모양 바꾸기. 지도 버튼, 정박 안내, 조작 안내 위치, `?` 버튼, 텔레포트 전환 색, 지도 섬 모양과 목록 카드 | `SailingHud`, `MapOverlay`, `ko.ts` | 중간 |
| U4 | 섬 패널 다시 짜기. 로더가 이미지(`source` 제외)를 넘기게 하고, 새 순서, 이미지 넘기기와 크게 보기, 본문 두 문단 자르기, 이전과 다음 섬 | `projects.server.ts`, `types.ts`, `IslandPanel`, `sailing.svelte.ts` | 큼 |
| U5 | 등대섬 패널. 프로필 로더를 만들고 `profile.md`를 보여 준다 | 새 `profile.server.ts`, `IslandPanel` 또는 새 `LighthousePanel` | 중간 |
| U6 | 진입 카드와 프로젝트 바로가기, 주소 `#project-<slug>`로 시작하기 | `+page.svelte`, 새 `EntryCard` | 중간 |
| U7 | 목록 페이지와 프로젝트 개별 페이지 | `list/+page.svelte`, 새 `projects/[slug]/` | 큼 |
| U8 | 모바일 정리. 시트 손잡이와 두 높이, 정박 버튼 위치, 조작 안내 시간 | `IslandPanel`, `SailingHud`, `Joystick` | 중간 |

- U1과 U2가 끝나야 나머지가 같은 토큰을 쓴다. U3부터 U6은 서로 다른 파일이라 나눠서 동시에 해도 된다. U7은 U4의 이미지 전달과 U5의 프로필 로더를 다시 쓴다.
- 결정 1, 2, 5는 U1 전에, 결정 3과 4는 U4와 U6 전에 정해야 한다.
- 새 화면 문구는 모두 `ko.ts`에 넣고, 저장소 `CLAUDE.md`의 글쓰기 기준을 따른다.
